# 小型 ESP32 無人機：散件、螺絲與焊接的重新評估

查核日期：2026-09-05。用途：個人專案研究紀錄，非課程共同採購要求。

狀態：只完成公開資料與程式靜態查核；未購買、編譯、量測或實機飛行。

## 本次結論與修正

使用者希望在蝦皮分別選購零件，自行鎖螺絲、插接線材及撰寫手機 App，可接受小型機體，而且目前不會焊接。

這個方向有條件可行。機構固定、電氣接線、控制程式是三件不同的工作，不能把「自製」等同於「全部親手焊接」，也不能把「目前未找到完整相容的蝦皮清單」等同於「技術上不可能」。

先前說明須修正：

- 跨品牌、跨賣家搭配不是問題本身；應檢查尺寸、孔距、電壓、電流、接頭極性、訊號協定及重量。
- 不一定要把 ESP32、IMU 和驅動全部整合成一片板。分立模組也可以，但每段連接、供電與固定都要解決；整合板只是減少接線的一種方法。
- 螺絲端子能形成電氣連接，不是物理上不能用。合格產品甚至具備抗振設計；微型飛行器的限制在於端子及轉接板的重量、體積、適用線徑、線材固定和電流規格。不能概括宣稱「只要震動就會鬆脫」。[Phoenix Contact 螺絲連接技術](https://www.phoenixcontact.com/en-gb/technologies/connection-technologies/screw-connection)
- 把飛行器縮小，不會自動使免焊更容易。較小的動力系統對多出的接頭、螺絲端子和線材重量更敏感。這是工程判斷，並非本專案已量測結果。

## FixedPID 作者到底公開了什麼

### FixedPID 函式庫

查核 commit：`4e9da5fee0c8005ba340ae7ebb8f4a7c422658ca`。

專案包含 README、LICENSE、`src/FixedPID.cpp`、`src/FixedPID.h`、`examples/basic.ino` 和 `test/test.cpp`。範例以固定的目標與輸入數值呼叫 PID，再印到 Serial，沒有操作 IMU 或馬達。這能在 ESP32 開發板接 USB 時研究，不必先做一台無人機。

README 的 ESP32-C3 160 MHz 最新自報基準為 P 2.630 μs、PI／Full PID 4.830 μs，與 FB 貼文的 2.2／4.3 μs 不同。這是函式執行時間，不能視為整架無人機的性能或飛行成功證據。本次未重跑其測試或效能量測。[FixedPID 固定版本](https://github.com/citycafe578/FixedPID/tree/4e9da5fee0c8005ba340ae7ebb8f4a7c422658ca)

### 作者另有 esp32Drone 專案

查核 commit：`f0cab22015b9d8de1bbec472697734510dce9618`。

該專案包含前端、Python 橋接程式，以及 `hardware/drone`、`hardware/ground`。由目前機上程式可確認：

- PlatformIO 設定使用 `esp32-c3-devkitm-1` 作為 board 定義；這不能單獨證明實體 PCB 的版型。
- 使用 MPU6050 與 AutoPID，目前機上程式沒有引用 FixedPID。
- 目前接收鏈路使用 ESP-NOW；較舊的 `FLOWCHART.md` 仍描述 NRF24L01，不能混為同一版本。
- `writeMotorUS()` 將 1000–2000 映射為 14-bit LEDC 的 819–1638，搭配 50 Hz，約對應 1–2 ms 脈波；實際油門另有限幅。

這種脈波形式符合常見 RC ESC 的控制方式。由此可推論程式預期有外部 ESC 或相容的馬達控制介面；不能據此確認 ESC 料號、馬達尺寸、有刷／無刷或連接器型號，也不能把它直接當成我們的 QX110＋8520 四路 MOSFET 架構。[機上程式](https://github.com/citycafe578/esp32Drone/blob/f0cab22015b9d8de1bbec472697734510dce9618/hardware/drone/main.cpp)、[PlatformIO 設定](https://github.com/citycafe578/esp32Drone/blob/f0cab22015b9d8de1bbec472697734510dce9618/hardware/drone/platformio.ini)

檢查上述版本的非第三方檔案後，未找到可核對的完整機體 BOM、電源原理圖、PCB 製造檔或可辨識接線方式的組裝說明。因此仍不能斷言作者是焊接、插頭、螺絲端子，或混合使用。FB 的「手搓」本身不足以判定。

## 哪些部分能鎖螺絲

| 工作 | 可使用的方法 | 焊接是否必要 |
|---|---|---|
| 主板與機架固定 | 螺絲、固定柱、適配的卡扣 | 通常不需要 |
| 馬達固定 | 有刷空心杯常用壓入式支架；有螺絲孔的無刷馬達可鎖螺絲 | 固定本身不需要 |
| 電池安裝 | 固定架或束帶，加上已配對的插頭 | 有合適的現成線材時不需要自己焊 |
| 馬達與驅動接線 | 預先接好的插頭線，或焊接到驅動板 | 若只賣裸線／焊盤，仍需有人加工 |
| ESP32 與 IMU 接線 | 預焊插座、配對線束，或焊線 | 視實際板卡與接頭而定 |
| MOSFET、穩壓器、電容等板上電路 | 買已裝好的模組或委託 PCB 組裝 | 電路製造通常包含焊接，但不必由使用者完成 |

所謂「免焊」通常是組裝者不用焊接，板上的元件和插座已由供應商焊好。若散件皆為裸線、裸焊盤與散裝電子元件，單靠機構螺絲不能完成這些電路。

## 兩個實際參考，避免只憑想像判斷

Flix 是另一個明確以通用零件自製的小型 ESP32 無人機專案，列出 ESP32 Mini、IMU 模組、四顆 8520、55／65 mm 槳與 MOSFET，並提供機架列印檔、原理連接圖及飛行示範。它同時列出機架／IMU 固定螺絲和烙鐵，組裝步驟包含焊接，正好說明小型散件機通常會混用機械固定與電氣焊接。這是「小型散件可行」的參考，不是免焊採購清單，也不是本專案已驗證的接線。[Flix 專案](https://github.com/okalachev/flix)、[組裝說明](https://github.com/okalachev/flix/blob/master/docs/assembly.md)

pyDrone 的官方組裝文件則明確說明免焊，馬達線接頭直接插主板。它證明 ESP32 小型無人機可以採插接式組裝；我們可研究這種連接方式，沒有因此必須購買完整套件。[pyDrone 組裝說明](https://wiki.01studio.cc/docs/pydrone/intro/assembly/)

## 對本專案的重新判斷

1. 全部使用裸板、裸線、散裝 MOSFET，只鎖螺絲：目前沒有完成電路的方法，不應據此下單。
2. 蝦皮跨店購買已焊好模組、插頭馬達、電池和相容機架：技術上可行，但尚未取得每一項都能直接對接的確切料號，仍不能宣稱已完成免焊 BOM。
3. 以開源小型機設計為基準，請供應商完成指定接頭焊接，再自行裝機與寫 App：使用者已同意店家預焊飛控的馬達與電源接頭，現採此方向進一步查核。這不等於已批准重新設計／製造電路板；供貨與詢價需求見[預焊組裝方案](prewired_build_plan.md)。

後續應從「可取得且可自行編譯韌體的 ESP32 控制板、驅動板和線束」向外選機架、馬達、槳及電池。尺寸先以有護圈的小型機作方向，待確切零件與總重量確定後才固定；不為追求最小尺寸先買 65 mm 機架，也不因目前尚未找到料號就排除所有散件路線。

若使用一般 STM32 飛控板並外掛 ESP32 當手機通訊橋接，雖然可以另作方案，但飛行穩定控制已不是 ESP32 執行，不能冒充原本要求的 ESP32 飛控。
