# Week 2～6 硬體課程教材設計藍圖

> 狀態：課程設計草案。這份文件先固定硬體學習順序、共同器材、實驗成果與
> 驗證門檻，不取代各週學生教材，也不是正式購買通知。

## 一、設計目標

Week 2～6 形成一條連續的硬體學習路徑：

```text
Week 2：確認開發板、基本接線、按鈕輸入與Serial證據
  → Week 3：電阻、電壓、GPIO與ADC基礎量測，並用1kΩ／10kΩ實作分壓
  → Week 4：判斷KY-018與DHT11資料是否可信
  → Week 5：安全控制會發光、發聲或移動的輸出
  → Week 6：把輸入、狀態、決策與輸出組成單機作品
  → Week 10：將已經能單機運作的事件接入Backend與手機
```

這五週不以介紹最多模組為目標。每一項新硬體都必須讓學生完成辨識、接線、
程式、預期結果、異常測試、故障排查及器材復原。Week 10以前不引入HTTP、
WebSocket、MQTT或Backend操作。

## 二、共同教材形式

Week 3～6沿用Week 2 `week2_main.ipynb`的學生實驗手冊寫法，每週教材應包含：

1. 本次可觀察成果與學習目標。
2. 依操作順序列出的實驗流程表，包含開始狀態及完成條件。
3. 實際使用的器材、課前條件與本週不使用的器材。
4. 在第一次影響操作時出現的名詞解釋。
5. 斷電、上電、電壓、極性、共地與電流風險。
6. 清楚的接線表、接線圖及實物辨識照片。
7. 完整程式、建立方式、編譯、上傳與預期Serial輸出。
8. 正常、邊界、重複及故障情境。
9. 依症狀整理的第一個安全排查動作。
10. 實驗紀錄、完成檢核與器材復原。

教材正文不放授課時間、教師講稿或個別口頭題目。現階段不以「必做／選做」
標籤切割正文；學生先依同一條共同路徑完成實驗，進度較快者再從教材末端的
變化題繼續修改、比較與測試。

每個一般教學週的收尾練習只選一個當週核心主題，依「理解概念、觀察現象、
比較或修改、用證據下結論」連續加深。不得以數個互不相關的小任務湊成收尾；
技術名詞與基準機制優先連到直接相關的官方文件或官方範例，課程自行加入的
示意資料、變數名稱與活動程序則明確標示為教學改寫。

## 四、Week 2：開發板、GPIO與量測基礎

### 教材狀態

完整學生教材已存在：

- `IoT_Introduction/Week_02_ESP32_Hardware_Basics/week2_main.ipynb`
- `docs/images/wiring/week2_gpio4_gpio5.svg`

### 固定成果

- 使用ESP32-S3-DevKitC-1 N16R8及USB-to-UART路徑。
- 按鈕接到教師以同批板卡完成 target test 後公布的`PIN_BUTTON`，並以
  `INPUT_PULLUP`讀取。
- 教師公布的`PIN_TEST_OUTPUT`只作安全測試輸出，不接負載。GPIO4與GPIO5
  在實機驗證完成前都只是候選腳位，不是學生可直接照抄的固定答案。
- Serial顯示按下、放開與時間。
- 萬用電表先完成麵包板與按鈕的斷電通斷；KY-018板上電阻、上電電壓與ADC量測
  由Week 3獨立處理。
- 以三項連續練習先解釋contact bounce與去抖演算法，再區分raw／stable事件，最後
  在相同線路下比較0／10／30／100 ms去抖時間並寫出有證據及限制的結論。

### 進入Week 3前的條件

- 學生可以辨認GPIO、GND、3V3與5Vin；Week 3會實測3V3與GPIO電壓，並辨認5Vin的外部輸入方向。
- 學生可以獨立完成Verify、Upload及Serial Monitor。
- 學生知道任何改線及通斷量測前先斷電。
- 教師已完成指定板卡、USB線及Week 2線路的實機驗證。

## 五、Week 3：電氣量測與ADC基礎

### 統一器材

- ESP32-S3、USB資料線、麵包板及杜邦線。
- KY-018光敏模組一個。
- 每組1～3人並自行準備一台萬用電表；1人組可向其他組共用，但各組分別保存
  量測與判讀證據。
- 固定電阻與光敏電阻概念先使用KY-018板上的`R1`與光敏元件，收尾再取必買電阻包
  的1kΩ與10kΩ各一顆做分壓。5kΩ只作計算示例，不增加採購。

KY-018在本週只作為可改變的類比輸入來源；正式校正、門檻與資料品質判讀
留到Week 4。本週不接DHT11、致動器或外部電池。

### 學習成果

完成Week 3後，學生應能：

1. 選擇合適量程比較KY-018板上固定電阻與光敏電阻路徑，並保留測點、光線條件、檔位、數值與單位。
2. 以GND為共同參考量測3V3與GPIO LOW／HIGH，並辨認本板5Vin是外部輸入而非目前的USB 5V輸出。
3. 用量測位置、檔位、數值與單位說明一筆電表結果。
4. 解釋電壓是兩點之間的差，並說明GND在本次量測中的共同參考作用。
5. 分辨數位LOW／HIGH與ADC原始值，不把ADC數字直接稱為伏特或亮度單位。
6. 只在遮光與室內光兩種條件下取得KY-018原始值，不增加手機手電筒亮光條件。
7. 說明單次數字只能證明當下讀值，尚不能證明感測器已完成校正或資料可信。
8. 自行辨認兩顆固定電阻並搭分壓，預測、量測與解釋交換上下位置後的電壓差異。

### 實驗順序

1. 板卡與KY-018均斷電，量測模組三組腳位路徑，比較固定值與隨光線改變的電阻。
2. 建立PGND與P3V3測試點，先做斷電短路檢查，再量3V3；另以實物絲印辨認5Vin與開路的IN-OUT焊盤，不接線或焊接。
3. 使用自動切換程式量測GPIO測試輸出的LOW／HIGH；Reset後只保存`startup=LOW`
   Serial命令，不重複量測0 V。Reset瞬間與完整安全啟動留到後續狀態機／安全單元。
4. 再次斷電，辨認KY-018的VCC、GND、訊號與實物方向。
5. 核對Week 3指定ADC GPIO及供電，再建立KY-018接線。
6. Upload最小ADC讀取程式，觀察原始值是否隨光線改變。
7. 遮光與室內光各記一筆S電壓及10筆ADC raw，共20筆raw，只比較變化與重複性；門檻、校正及
   有效／無效資料留到Week 4。
8. 完成同一分壓主題的Discussion後，斷電拆除KY-018與GPIO線；辨認並量測獨立的
   1kΩ與10kΩ，依主教材第13.7節接到3V3、GND與電表，量測兩種上下配置。
   交換電阻前必須拔USB，不使用電流檔，不重做光線或ADC實驗。
9. 斷電、恢復器材並保存量測表、Serial log、分壓預測與第一個安全排查動作。

### Serial資料格式

Week 3先使用容易閱讀的單行文字，不提前教授JSON或感測狀態：

```text
device=student01 uptime_ms=12500 light_raw=1840
```

本週只說明`light_raw`是ADC原始讀值；Week 4完成校正與有效性判斷後才加入
`light_state`、`valid`與`reason`。

### 教材證據

- 電阻、3V3與GPIO LOW／HIGH量測表、Reset後Serial啟動命令，以及5Vin外部輸入辨識紀錄。
- KY-018接線表、清楚照片及遮光／室內光各10筆原始值與一筆S電壓。
- Discussion「數字變大，就代表光比較亮嗎？」：以分壓接法、兩組資料、紙上排查
  與限制逐步作答；固定電阻練習另保存兩顆獨立阻值、兩種配置的預測與電壓實測、
  接線照片及比例解釋。5kΩ不另列一份必交紙上作業。
- 一次接線或量測異常、第一個安全檢查動作、修正及復原結果。

### 發布前驗證門檻

- 實物確認KY-018接腳順序、供電電壓與輸出形式。
- 選定並實測ESP32-S3 ADC GPIO。
- 鎖定Arduino-ESP32版本並完成compile與target test。
- 記錄遮光與室內光兩種條件的ADC原始範圍。
- 建立量測點、接線圖、預期Serial輸出及Lab Note。
- 1kΩ／10kΩ固定分壓為2026-09-05新增學生練習，尚未進行實機驗證；須先依主教材
  完成20／25／30列接線、阻值確認、兩種配置電壓與安全復原的實測紀錄。

## 六、Week 4：感測器與輸入品質

### 統一器材

- ESP32-S3、USB資料線、麵包板及杜邦線。
- KY-018光敏模組一個。
- YS-31 DHT11溫溼度模組一個。

全班統一使用KY-018與DHT11，不從PIR、HC-SR04、OLED或其他模組中任選。
PIR、HC-SR04及OLED保留為教師示範或第7週後的專題選配。

### 學習成果與實驗順序

1. 以Week 3遮光與室內光原始值為起點；Week 4原定的第三種亮光條件須在本週
   另取資料，不假設Week 3已完成。對本週三種光線條件各取固定筆數，計算min、max及average。
2. 依自己量到的資料建立DARK、NORMAL及BRIGHT門檻，不直接複製教材數字。
3. 斷電後更換為DHT11接線，安裝並記錄已驗證的library版本。
4. 依DHT11允許的取樣方式讀取溫度與濕度，保留單位並比較過快取樣。
5. 辨認讀取失敗、超出合理範圍、線路鬆脫及更新過快等無效狀態。
6. 只在資料有效時產生作品狀態，無效時輸出可診斷的錯誤原因。
7. 使用教材指定、可重現且安全的無效資料情境；KY-018訊號線懸空不保證
   產生固定錯誤值，不得把拔線當成唯一故障注入方法。
8. 恢復正確接線，完成三次正常流程及一次故障後復原。

### Serial資料與教材證據

```text
device=student01 uptime_ms=12500 light_raw=1840 light_state=NORMAL temperature_c=26.3 humidity_pct=61.0 valid=true reason=none
```

學生保存兩張接線表、三種光線條件的重複量測、門檻及理由、DHT11正常與
無效紀錄、一筆有效與一筆無效資料，以及一次故障、修正及復原結果。發布前
須確認實物腳位、ADC與DHT11 GPIO、供電、library版本、取樣間隔、compile及
target test；這些欄位到Week 10才轉成JSON傳送。

## 七、Week 5：致動器、外部供電與安全停止

### 統一器材

- ESP32-S3、USB資料線、麵包板、杜邦線及按鈕。
- KY-016 RGB LED模組一個。
- KY-012有源蜂鳴器一個。
- SG90 180度舵機一個。
- 4AA帶開關電池盒一個，由學生個人自購。
- 指定種類的AA電池、每組萬用電表及安全電源轉接方式。

WS2812、MG90S、LM2596、6AA電池盒、L298N及DC馬達不列入共同實驗。

### 學習成果

完成Week 5後，學生應能：

1. 分辨GPIO控制訊號與致動器電源。
2. 使用RGB及蜂鳴器表達READY、ACTIVE、SUCCESS及ERROR等狀態。
3. 量測電池盒極性、空載電壓及舵機動作時的負載電壓。
4. 讓SG90使用外部電源，並讓外部電源GND與ESP32 GND共地。
5. 限制舵機角度、動作時間及重新開機後的位置。
6. 在錯誤輸入、timeout或重啟時回到已驗證的安全狀態。
7. 由Serial log說明requested、applied、stopped或rejected結果。

### 實驗順序

1. 全部斷電，辨認RGB、蜂鳴器、SG90及電池盒的腳位與極性。
2. 先不接SG90，分別測試RGB狀態及蜂鳴器短聲提示。
3. 建立明確的`setOutputState()`，一次設定所有低功率輸出。
4. 在電池盒開關關閉時完成外部供電、共地及SG90訊號接線。
5. 先量空載電壓，確認極性及範圍後才接上舵機。
6. 舵機不帶機構，從安全角度開始，只移動小範圍。
7. 量測動作時電壓，觀察ESP32是否重啟、舵機是否抖動或線材是否發熱。
8. 使用按鈕要求一次動作；程式限制角度、時間及連續命令。
9. 測試timeout、重啟及不合理角度，確認舵機回到安全位置或拒絕動作。
10. 斷電、拆除電池，再整理接線與測試紀錄。

### Serial資料格式

```text
device=student01 event=actuator_command requested_angle=90 applied_angle=90 result=done reason=none
device=student01 event=actuator_command requested_angle=200 applied_angle=SAFE result=rejected reason=out_of_range
```

這些欄位會在Week 10加入`command_id`，形成手機命令與實體結果的追蹤路徑。

### 教材證據

- 電源、共地、RGB、蜂鳴器及舵機接線表。
- 電池盒空載與舵機動作時電壓。
- 舵機安全角度及選擇理由。
- 正常動作、timeout、拒絕命令與重新啟動測試。
- 一次供電或控制異常及修正紀錄。

### 發布前驗證門檻

- 確認實際SG90型號、允許電壓、訊號及安全角度。
- 實測學生可自備的AA電池種類，並決定可接受規格及低電量判定。
- 決定電池盒裸線到麵包板或舵機的防短路轉接方式。
- 選定並實測PWM GPIO、RGB GPIO及蜂鳴器GPIO。
- 鎖定ESP32Servo等library版本並完成compile、供電及target test。
- 測試斷電順序、重啟、timeout、舵機卡住與低電壓現象。

## 八、Week 6：單機互動作品

### 共同參考作品

全班先建立同一個「光線互動狀態裝置」，再改變情境、門檻、提示或機構：

```text
START按鈕開始；STOP按鈕可在任何實體流程進入ERROR
  → 讀取KY-018並建立或載入門檻
  → RGB顯示目前狀態
  → 光線條件成立時，蜂鳴器短聲並讓SG90完成一次受限動作
  → 顯示結果並回到可再次操作的狀態
  → 感測無效、超時或重新啟動時回到ERROR／安全位置
```

DHT11在Week 6可保留為第二項狀態資訊或錯誤來源，但不要求所有輸入與輸出
同時塞進單一程式。教材應優先讓狀態、停止與重複測試清楚。

### 固定狀態

| 狀態 | 進入原因 | 實體輸出 | 離開條件 |
|---|---|---|---|
| IDLE | 開機或流程結束 | 舵機安全位置、提示關閉 | 按下START按鈕 |
| READY | 接受開始 | 顯示準備狀態 | 門檻及感測資料有效 |
| ACTIVE | 開始監測 | 顯示執行狀態 | 條件成立或timeout |
| RESULT | 成功觸發 | 一次受限動作及短聲提示 | 顯示完成後回IDLE |
| ERROR | STOP、感測無效、timeout或不安全命令 | 舵機安全位置及錯誤提示 | 問題修正並Reset |

### 學習成果

1. 將輸入、狀態、決策與輸出分成可說明的程式區塊。
2. 不使用長時間`delay()`阻塞按鈕、感測或安全停止。
3. 每次進入狀態時明確設定所有輸出，不依賴上一個狀態留下的結果。
4. 完成三次從IDLE開始、回到IDLE結束的流程。
5. 製造一次感測異常或timeout並進入ERROR。
6. 由狀態圖、Serial log及實物行為證明三者一致。

### 實驗順序

1. 畫出狀態、進入原因、輸出及離開條件。
2. 先用Serial完成不接致動器的狀態轉換測試。
3. 加入START、獨立實體STOP及KY-018，確認READY、ACTIVE與ERROR條件。
4. 加入RGB與蜂鳴器，讓狀態在實物上可見。
5. 最後接入已由Week 5驗證的SG90供電與安全動作函式。
6. 完成正常流程三次，逐次記錄開始、結果及經過時間。

## 十、教材製作順序

1. 完成Week 2指定板卡及接線的target test，更新`docs/hardware_state.md`。
2. 已從舊Week 3 notebook拆出電壓、GPIO與ADC內容，完成新
   `Week_03_Electrical_Measurement_and_ADC/week3_main.ipynb`；2026-09-05依教師最新要求，
   在KY-018板上電阻概念之外加入1kΩ／10kΩ實作分壓。各項實測狀態以
   `docs/hardware_state.md`為準，不能將計算或已有KY-018測試當作新分壓接法已通過。
3. 實測KY-018與YS-31 DHT11，固定Week 4 GPIO、library及資料格式，再完成
   `week4_main.ipynb`。
4. 實測4AA、SG90、RGB與蜂鳴器供電，固定Week 5安全接法並完成
   `week5_main.ipynb`。
5. 使用已驗證的Week 3至5元件組合Week 6狀態機，完成`week6_main.ipynb`、
   狀態圖、完整程式及故障測試表。
6. Week 1正式材料清單已依共同實驗依賴固定；五週教材完成後再次核對清單，
   只有實機驗證發現安全或相容性問題時才修正品項，並記錄變更原因。
