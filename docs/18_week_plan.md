# 18 週課程規劃：Full-stack IoT 系統設計與實作

本課程以資管學生擅長的程式與資訊系統整合為主軸，硬體只作為真實世界的輸入與輸出。學生不是為了接一顆感測器而做 IoT，而是要完成一套包含 ESP32-S3 裝置端、網路通訊、學生自行撰寫的後端、資料庫、Log、手機前台及異常處理的完整 IoT 系統。

教師的智慧停車場與 UCI K-4 4WD 是跨層整合參考案例，不是學生共同必做作品。學生第 8 週提出自選題目並展示技術可行性片段，第 13-17 週完成同一題目的完整系統。

## 一、完整作品的共同架構

每組期末作品至少要能說明並展示下列雙向資料流：

```text
感測器／輸入
  -> ESP32-S3
  -> Wi-Fi + HTTP 或 MQTT
  -> 學生自行撰寫的 Backend
  -> Database + structured Log
  -> WebSocket
  -> 手機前台（Responsive Web／PWA 或 Flutter）

手機操作
  -> Backend 驗證、記錄與派送命令
  -> ESP32-S3 執行實體輸出
  -> 回傳結果
  -> 手機前台更新狀態
```

手機前台不能只顯示數字；至少要能查看即時狀態、查詢歷史資料、執行一項控制或設定，以及呈現裝置離線或錯誤狀態。Responsive Web／PWA 是全班預設路線，Flutter 可作進階替代。

## 三、第 7-9 週期中安排

第 7 週的個人筆試與第 8 週的小組面談評量不同能力，不重複考核。

### 第 7 週：個人情境式筆試

筆試約 50-60 分鐘，題目以接線圖、JSON、資料流、通訊選擇、短程式與 Log 診斷為主，不以背誦名詞為主。其餘時間讓學生形成期末題目草案。

### 第 8 週：每組只來一次的概念與可行性面談

每組預約 12-15 分鐘，只需參加一個時段。面談內容如下：

1. 誰在什麼情境下遇到什麼問題。
2. 裝置、Backend、Database、手機前台之間的資料流。
3. 一個已經可以運作的技術片段，不要求完整產品。
4. 預計使用的材料、手機操作、資料保存與 Log。
5. 最大三項風險、最小可驗收版本與預計限制。

第 8 週面談資料就是期中小組成果，不另設「作品整合」、「非同步證據包」或返國後重複驗證。

### 第 9 週：出國期間

教師於 2026-11-01 至 2026-11-07 出國參加研討會。2026-11-04 不要求學生到校、不安排同步考試，也不收新的期中作品。選讀 QA 只協助學生準備第 10-12 週，不列為高權重評量。

## 四、第 10-12 週共同進階模組

三週分別補齊完整 IoT 的通訊、資料與手機互動：

| 週次 | 核心問題 | 不可只做到 | 應完成的證據 |
|---:|---|---|---|
| 10 | 多台裝置如何交換資料、派送命令並判斷在線狀態？ | 只成功 publish 一筆資料 | Topic contract、Last Will、online／offline 與 command acknowledgement |
| 11 | 系統如何保存、查詢並用 Log 解釋發生過的事？ | 只在 Serial Monitor 看即時值 | Database schema、歷史 API、結構化事件、至少一項統計或診斷 |
| 12 | 使用者如何用手機完成完整工作，而不只是看 Dashboard？ | 只顯示一個感測數字 | 即時狀態、歷史資料、一項操作、錯誤／離線呈現與使用者流程 |

## 五、第 13-17 週專題檢核

| 週次 | 檢核目的 | 教師核心追問 |
|---:|---|---|
| 13 | 確認完整垂直切片，而不是各層分開完成 | 真實資料是否已經從裝置進入資料庫並出現在手機？哪一段仍是假資料？ |

| 17 | 評量完整系統與個人理解 | 每位成員能否追蹤一條資料流、解釋自己的決定並現場定位問題？ |

## 六、期末作品最低要求

- ESP32-S3 與至少一種實體輸入、至少一種實體輸出。
- Wi-Fi，以及 HTTP 或 MQTT 裝置通訊。
- 學生自行撰寫並可重建的 Backend。
- Database schema、歷史資料查詢與 structured Log。
- 可在手機使用的前台，包含即時狀態、歷史資料、一項操作及錯誤呈現。
- WebSocket 即時更新。
- 至少一項自動規則、狀態機或排程。
- 至少三種測試情境，其中一種必須是斷線、錯誤輸入、感測異常或服務停止。
- 裝置端、前台與後端原始碼，以及接線圖、資料流圖、API／Topic／JSON contract、BOM、部署／重建步驟、AI 使用紀錄與已知限制。

Blynk、ThingSpeak、Node-RED 或現成 Dashboard 可以作輔助工具，但不能取代學生自行撰寫的裝置端、Backend、Database 與手機前台核心成果。

## 八、教師參考案例與延伸路線

- 教師智慧停車場與 UCI K-4 4WD：示範感測、狀態機、事件紀錄、手機監控與故障復原。
- 智慧教室：占用、環境、燈光、告警與能源管理流程。
- 夾娃娃機或互動機台：手機操作、權限、命令佇列、致動器與操作紀錄。
- 倉儲、置物櫃與設備借還：識別、狀態、歷史與異常追蹤。
- 手機視覺：手機／筆電先完成影像判斷，再將結果送入 Backend 控制 ESP32-S3。
- ROS 2、Gazebo 與 Nav2：第 18 週作為從完整 IoT 系統走向機器人系統的進階路線。
