# 115-1 物聯網與雲端運算課程教學大綱（重新規劃版）

本文件供填寫國立臺北商業大學課程教學大綱使用。課程以教師開發的智慧停車系統作為跨層整合案例；學生不必製作車輛。各組於期中提出自選題目並展示最小技術可行性片段，期末完成包含 ESP32-S3、學生自行撰寫的 Backend、Database、structured Log、手機前台及異常處理的完整 Full-stack IoT 系統。

## 二、教學目標（可直接貼入）

本課程以低成本、可連網、可觀測及可管理的 IoT 系統為主軸，帶領資管學生學習 ESP32-S3、感測器、致動器、安全接線、Wi-Fi、HTTP、MQTT、WebSocket、JSON、Backend、Database、structured Log 與手機前台。教師開發的智慧停車系統作為跨層整合案例，用來說明感測、控制、通訊、資料、狀態機、測試及使用者流程如何形成完整系統；學生不必製作車輛。每組學生於期中提出自選題目並展示一個可運作的技術可行性片段，期末完成具有雙向手機操作、資料保存、自動決策、Log 分析、異常處理及場域價值的 Full-stack IoT 作品。課程重視系統整合、測試證據、故障處理、安全、協作，以及 AI 輔助開發後的人工作業與驗證。

## 四、教學內容（可直接貼入）

課程內容分為四個階段。第一階段以密集小作品建立 ESP32-S3、安全接線、感測／輸出、HTTP／JSON、Backend、WebSocket 與手機即時畫面的共同能力。第二階段以個人情境式筆試檢核共同概念，各組再透過期中面談提出使用者問題、完整架構、技術可行性片段、材料與風險。第三階段介紹 MQTT 多裝置通訊、Database schema、歷史 API、structured Log、資料分析、Responsive Web／PWA 與雙向手機控制。第四階段由學生完成自選 Full-stack IoT 系統，經歷完整垂直切片、自動規則、同儕使用、故障注入、版本凍結及可重建成果包，於第 17 週展示作品；第 18 週不新增評量進度。

## 五、作品與指定技術

### 期中成果：概念與技術可行性面談

第 8 週每組只參加一次 12-15 分鐘面談，不要求完成完整專題。每組須說明目標使用者與問題、裝置到手機的預計資料流、前後台責任、材料、Database／Log 構想、三項主要風險與驗收條件，並展示一個已可運作的技術片段。面談資料就是期中小組成果，不另設非同步證據包或返國後重複驗證。

### 期末作品：完整 Full-stack IoT 系統

每組至少完成：

- ESP32-S3、至少一種實體輸入及至少一種實體輸出。
- Wi-Fi，以及 HTTP 或 MQTT 裝置通訊。
- 學生自行撰寫、可啟動並可重建的 Backend。
- Database schema、歷史資料查詢及 structured Log。
- 可在手機使用的 Responsive Web／PWA 或 Flutter 前台。
- 手機前台可查看即時狀態、查詢歷史資料、執行一項操作並呈現離線／錯誤狀態。
- WebSocket 即時更新，以及命令執行結果回傳。
- 至少一項自動規則、狀態機或排程。
- 至少三種測試情境，其中一種為斷線、錯誤輸入、感測異常或服務停止。
- 裝置端、Backend 與手機前台原始碼，以及接線圖、資料流圖、API／Topic／JSON contract、BOM、部署／重建步驟、AI 使用紀錄與已知限制。

Blynk、ThingSpeak、Node-RED 或現成 Dashboard 可作輔助工具，但不能取代學生自行撰寫的裝置端、Backend、Database 與手機前台核心成果。

## 六、教師整合案例：智慧停車系統

教師於學期中逐步完成感應停車場、UCI K-4 4WD、距離感測、事件紀錄與即時 dashboard，作為課程的參考架構與期末示範。學生可分析、測試或沿用其中的資料格式與設計概念，但不以造車、自主停靠或硬體速度作為學生共同必修評量。

## 七、教學方法

- 每個重要概念採 6-12 分鐘短講解，接續 Think-Pair-Share、HOT question 或 2-5 分鐘 BIT（Brief Interactive Task）。
- BIT 使用 Predict、Classify、Transform、Rank、Debug 或 Completion，並留下表格、流程圖、接線圖、pseudo-code、log 或測試結果。
- 教師先要求理由與證據，再給延後回饋；依可見的 learning evidence 決定是否補救或進入下一階段。
- 實作採 3-4 人分組及角色輪替；硬體接電及致動器測試前須通過安全 checkpoint。
- 每組維護 Lab Notebook，記錄目標、接線／資料流、成功證據、錯誤、修正、AI 使用與下一步。

## 十一、AI 工具使用規範

學生可使用生成式 AI 協助產生程式初稿、JSON、介面、測試案例或除錯假設，但須在 Lab Notebook 說明 AI 產出、人工修改、修改理由及驗證證據。不得直接執行未讀過、無法說明或未經基本測試的程式。評分依據為學生能否解釋、測試、修正及重現系統，而非是否使用或未使用 AI。

## 十二、硬體與資料安全規範

- 實作前確認板卡型號、腳位、邏輯電壓、電源極性及共地。
- ESP32-S3 GPIO 為 3.3V 邏輯；5V 訊號不得未經保護直接送入 GPIO。
- 馬達或舵機不得由 GPIO 直接供電，致動器須具備安全停止或斷電方式。
- 裝置斷網時須進入可預期的安全狀態；雲端或 dashboard 不作危險致動器的唯一緊急控制迴路。
- 專題不得未經同意蒐集可識別個人的影像、聲音或其他敏感資料。
