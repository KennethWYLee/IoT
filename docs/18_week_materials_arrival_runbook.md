# 18 週材料到貨後教學 Runbook

這份文件假設材料包已到貨，學生每組有一套核心材料，老師希望用 18 週帶學生從完全入門，到能完成智慧停車場、智慧教室，最後自由發展期末專題。

## 基本假設

- 每組 3-4 人，共用一片 ESP32-S3 與一套材料。
- 學生會寫程式，但硬體經驗弱。
- 每週以 2-3 小時課程設計；若課程時間較短，就把「挑戰任務」改成課後。
- 期中前共同做智慧停車場，期中後先做智慧教室，再進入自由專題。
- 視覺辨識使用學生手機與筆電，不要求買相機板或 Raspberry Pi。
- ESP32-S3 使用 Arduino IDE 或 PlatformIO 的 Arduino framework。
- Dashboard 先用簡單網頁或本機後端，不一開始要求雲端部署。
- PIR 與光敏若尚未到貨，最晚第 10 週前補齊。

## 材料到貨當天先做什麼

第一件事不是急著做停車場，而是讓學生建立「材料可以被我控制」的信心。

### 課前老師準備

- 準備材料包點收表。
- 準備 ESP32-S3 腳位圖。
- 準備 3.3V / 5V / GND 的簡短安全投影片。
- 準備 Arduino IDE 或 PlatformIO 安裝說明。
- 準備一份最小測試程式：Serial print、blink、Wi-Fi scan。

### 當天學生要完成

- 清點每組材料。
- 拍下材料包照片並建立 lab notebook。
- 成功讓 ESP32-S3 連上電腦。
- 成功上傳第一支程式。
- 看到 Serial Monitor 輸出。
- 控制一個 LED 或 RGB LED。

### 當天不要做

- 不要一次接上伺服、超音波、LED、蜂鳴器。
- 不要讓學生還沒懂 GND 就接多個模組。
- 不要讓 HC-SR04 Echo 直接接 ESP32-S3 GPIO。
- 不要一開始就做 MQTT、OpenCV、dashboard。

## 18 週總節奏

| 階段 | 週次 | 目的 |
|---|---:|---|
| 硬體信心建立 | 1-3 | 會上傳程式、會接基本元件、會連 Wi-Fi |
| 停車場實體控制 | 4-6 | 閘門、燈號、蜂鳴器、入口偵測、紙板模型 |
| 手機視覺與整合 | 7-9 | 手機影像、OpenCV、dashboard、期中 Demo |
| 第二 IoT 專案 | 10-12 | 智慧教室，多感測器推論與異常告警 |
| 自由專題 | 13-18 | 學生延伸成自己的題目，完成展示 |

## 第 1 週：材料開箱、開發環境、第一個輸出

### 主題

ESP32-S3 是什麼、Arduino framework 是什麼、材料安全與第一支程式。

### 使用材料

- ESP32-S3
- USB 線
- RGB LED 模組或板上 LED
- 杜邦線

### 課堂流程

1. 課程導入：這門課不是學某顆感測器，而是學「資料流 + 實體互動」。
2. 每組清點材料，拍照紀錄。
3. 安裝 Arduino IDE / PlatformIO 與 ESP32 board package。
4. 上傳 Serial print 測試。
5. 控制 RGB LED 或板上 LED。

### 最低交付

- 一張材料清點照片。
- 一段 10 秒影片：ESP32-S3 成功控制 LED。
- lab notebook 第一頁：今天遇到的問題與解法。

### 挑戰任務

- 讓 LED 每秒變色。
- 用 Serial Monitor 輸入 `red`、`green`、`blue` 控制顏色。

## 第 2 週：GPIO、GND、麵包板與按鈕

### 主題

輸入、輸出、GND 共地、麵包板接線安全。

### 使用材料

- ESP32-S3
- 麵包板
- 杜邦線
- 按鈕
- RGB LED
- 蜂鳴器

### 課堂流程

1. 用圖解講 GPIO、GND、VCC、Signal。
2. 示範麵包板哪裡互通，哪裡不互通。
3. 接按鈕，讀 HIGH / LOW。
4. 按按鈕控制 LED 或蜂鳴器。
5. 建立除錯流程：電源 -> GND -> 腳位 -> 程式 -> Serial。

### 最低交付

- 按鈕按下時 LED 變色。
- Serial Monitor 顯示按鈕狀態。

### 挑戰任務

- 做一個「管理員確認按鈕」：按下後蜂鳴器停止。
- 做防彈跳 debounce。

## 第 3 週：Wi-Fi、HTTP 與第一個 Web 控制

### 主題

ESP32-S3 連網，讓網頁可以控制硬體。

### 使用材料

- ESP32-S3
- RGB LED
- 蜂鳴器

### 課堂流程

1. 講 HTTP 是什麼：網頁呼叫 API。
2. ESP32-S3 連上 Wi-Fi。
3. ESP32-S3 開一個簡單 WebServer。
4. 網頁按鈕控制 LED 或蜂鳴器。
5. 回傳 JSON 狀態。

### 最低交付

- 手機或筆電瀏覽器可開 ESP32-S3 的控制頁。
- 可以用網頁切換 LED 顏色。

### 挑戰任務

- 加 `/status` API，回傳目前 LED、蜂鳴器、裝置在線狀態。
- 讓網頁每 2 秒自動刷新狀態。

## 第 4 週：SG90 伺服馬達與停車場閘門

### 主題

PWM、伺服角度、實體機構與緊急停止。

### 使用材料

- ESP32-S3
- SG90 伺服馬達
- 按鈕
- 紙板或竹籤

### 課堂流程

1. 講伺服馬達與一般馬達不同：控制角度，不是一直轉。
2. 示範 0 度、90 度、180 度。
3. 做紙板閘門。
4. 用網頁控制 open / close。
5. 加入按鈕作為緊急停止或手動關門。

### 最低交付

- 做出可開關的停車場閘門。
- 網頁可控制閘門開 / 關。

### 挑戰任務

- 閘門開啟後 5 秒自動關閉。
- 關門前蜂鳴器短嗶提醒。

## 第 5 週：RGB LED、蜂鳴器、入口偵測與安全降級

### 主題

用輸出元件表達狀態，用超音波偵測入口是否有車。

### 使用材料

- ESP32-S3
- RGB LED
- 蜂鳴器
- HC-SR04
- 電阻包或分壓電阻

### 課堂流程

1. 講狀態設計：綠燈可進、紅燈已滿、黃燈處理中。
2. 講 HC-SR04 的 Trig / Echo。
3. 強調 Echo 電壓問題：用分壓或 3.3V 相容模組。
4. 讀取距離並用 Serial 顯示。
5. 當入口距離小於門檻時，觸發燈號或蜂鳴器。

### 最低交付

- RGB LED 可表示至少三種狀態。
- 入口偵測到物體時，蜂鳴器或 LED 有反應。

### 挑戰任務

- 加入「入口有車但車位已滿」警示。
- 設計防誤判：距離連續 3 次低於門檻才算有車。

## 第 6 週：紙板停車場模型與資料模型

### 主題

把模型變成系統：車位、車輛、事件、狀態。

### 使用材料

- 紙板 / 珍珠板 / 膠帶 / 竹籤
- ESP32-S3 與前幾週元件
- 列印的車位標示或 ArUco / QR 標記

### 課堂流程

1. 每組設計至少 3 個車位。
2. 定義資料模型：slot_id、status、updated_at。
3. 定義事件：car_enter、car_leave、gate_open、gate_close。
4. 把第 4-5 週的閘門、燈號、入口偵測裝到模型上。
5. 畫出本組停車場資料流。

### 最低交付

- 完成紙板停車場模型。
- 至少 3 個車位有清楚標示。
- 能畫出資料流圖。

### 挑戰任務

- 加車牌或 QR 車輛識別。
- 設計預約車位或 VIP 車位。

## 第 7 週：手機當相機，筆電取得影像

### 主題

視覺辨識不先買相機板，用手機降低硬體門檻。

### 使用材料

- 學生手機
- 筆電
- 紙板停車場模型

### 課堂流程

1. 講相機板、手機、Raspberry Pi Camera 的差異。
2. 手機固定在穩定位置拍模型。
3. 筆電取得手機影像，可用網路攝影機、IP Camera app 或拍照上傳流程。
4. 用 Python / OpenCV 讀取影像。
5. 顯示畫面並標出車位區域。

### 最低交付

- 筆電成功看到手機拍攝的停車場畫面。
- 畫出至少 3 個 ROI 車位區域。

### 挑戰任務

- 做一個簡單校正流程：點選車位四角。
- 儲存 ROI 設定檔。

## 第 8 週：OpenCV 判斷車位空/滿

### 主題

讓影像變成資料。

### 使用材料

- 手機
- 筆電
- 停車場模型
- 玩具車、紙片或積木作為車輛

### 課堂流程

1. 講 ROI、顏色、輪廓、閾值。
2. 先用最簡單方法判斷：車位區域亮度、顏色或差異。
3. 判斷 3 個車位空 / 滿。
4. 輸出 JSON 狀態。
5. 討論誤判來源：光線、角度、遮擋、手機晃動。

### 最低交付

- 程式可判斷至少 3 個車位空 / 滿。
- 結果可輸出成 JSON 或印在終端機。

### 挑戰任務

- 加 confidence 分數。
- 用 ArUco / QR 輔助定位車位或車輛。

## 第 9 週：期中 Demo，智慧停車場 MVP

### 主題

整合手機視覺、dashboard 與 ESP32-S3 實體控制。

### 使用材料

- 前 8 週全部材料

### 課堂流程

1. 前半段整合測試。
2. 每組 5 分鐘 Demo。
3. 老師用同一張檢核表評分。
4. 課後提交簡短技術文件與影片。

### 期中最低標準

- 手機拍攝停車場模型。
- OpenCV 判斷至少 3 個車位空 / 滿。
- Dashboard 或網頁顯示車位狀態。
- ESP32-S3 控制閘門、燈號或蜂鳴器。
- 有至少一種事件紀錄。

### 建議評分

| 面向 | 比重 |
|---|---:|
| 硬體控制穩定度 | 25% |
| 視覺辨識可運作 | 25% |
| 資料流與 dashboard | 25% |
| 展示、文件、除錯紀錄 | 25% |

## 第 10 週：智慧教室感測器整合

### 主題

從停車場換到第二個 IoT 場域：教室占用與節能異常。

### 使用材料

- ESP32-S3
- DHT11
- KY-018 光敏電阻模組
- HC-SR501 PIR
- RGB LED

### 課堂流程

1. 說明第二專案不是按鈕簽到，而是自動推論。
2. 讀 DHT11 溫濕度。
3. 讀光敏亮度。
4. 讀 PIR 是否偵測到近期活動。
5. 組合成 JSON 上傳或顯示。

### 最低交付

- ESP32-S3 能讀出溫度、濕度、亮度、motion 狀態。
- Serial 或 dashboard 能看到資料。

### 挑戰任務

- 每 10 秒上傳一次。
- 加 device_id 與 room_id。

## 第 11 週：狀態推論與告警規則

### 主題

把感測資料轉成管理者看得懂的狀態。

### 使用材料

- 第 10 週全部材料
- 蜂鳴器或 RGB LED

### 課堂流程

1. 設計狀態：使用中、空置、疑似忘關燈、舒適度異常。
2. 建立規則：
   - motion_recent = true 且 light 高：使用中。
   - motion_recent = false 且 light 高超過一段時間：疑似忘關燈。
   - temperature 過高或 humidity 過高：舒適度異常。
3. Dashboard 顯示狀態。
4. ESP32-S3 用 LED 或蜂鳴器提示異常。

### 最低交付

- 系統可自動判斷至少 3 種教室狀態。
- Dashboard 顯示目前狀態與最後更新時間。

### 挑戰任務

- 加入時間條件，例如 5 分鐘無人但燈亮才告警。
- 告警後可用按鈕確認已處理。

## 第 12 週：第二專案 Demo 與期末提案診所

### 主題

完成智慧教室 MVP，開始把材料轉成自己的專題。

### 課堂流程

1. 每組展示智慧教室狀態推論。
2. 老師回饋：資料流是否完整、狀態是否合理、告警是否有意義。
3. 發布期末專題規格。
4. 每組提出 2 個期末題目候選。
5. 老師協助縮小範圍與材料需求。

### 最低交付

- 智慧教室 Demo。
- 期末專題候選題目 2 個。
- 初版 BOM 與風險表。

## 第 13 週：期末 Proposal

### 主題

從老師指定題目，轉成學生自己的 IoT 系統。

### 課堂流程

1. 每組提交 proposal。
2. 必須說清楚：場域問題、使用者、資料來源、ESP32-S3 控制什麼、dashboard 顯示什麼。
3. 老師審核是否過大、是否超出預算、是否安全。
4. 確定最低可行版本與挑戰功能。

### 最低交付

- 一頁 proposal。
- 資料流圖。
- BOM。
- 分工表。

### 可接受題目

- 智慧停車場完整版。
- 夾娃娃機或互動機台。
- 自走車入口管理。
- 教室占用與節能稽核。
- 倉儲貨位辨識。
- 座位占用偵測。
- 置物櫃管理。
- 腳踏車或機車停放管理。

## 第 14 週：Sprint 1，核心資料流跑通

### 主題

先跑通資料流，不急著做漂亮外殼。

### 課堂流程

1. 每組確認本週唯一目標。
2. 完成資料來源：感測器或影像。
3. 完成資料傳輸：HTTP 或 MQTT。
4. 完成 dashboard 初版。
5. 老師逐組檢查資料流。

### 最低交付

- 至少一筆真實資料能從現場進入 dashboard。
- 有簡單 log。

## 第 15 週：Sprint 2，實體控制或使用者流程

### 主題

讓系統不只是顯示資料，而是能做動作或支援流程。

### 課堂流程

1. 加入 LED、蜂鳴器、伺服或馬達控制。
2. 加入使用者操作流程，例如預約、開始、停止、確認告警。
3. 測試失敗狀況，例如 Wi-Fi 斷線、感測器誤判、裝置重開。

### 最低交付

- Dashboard 或後端可以控制至少一個實體輸出。
- 系統有基本錯誤處理或狀態提示。

## 第 16 週：整合測試與異常測試

### 主題

作品要能展示，也要能承受現場意外。

### 課堂流程

1. 每組做 10 分鐘連續測試。
2. 測試至少 3 種異常：
   - Wi-Fi 斷線。
   - 感測器讀不到。
   - 使用者操作錯誤。
   - 裝置重新啟動。
   - 影像光線改變。
3. 修正最嚴重的問題。
4. 整理展示腳本。

### 最低交付

- 測試紀錄表。
- 至少一個異常情境有處理方式。

## 第 17 週：展示彩排與文件整理

### 主題

把作品整理成別人看得懂、助教接得起來的系統。

### 課堂流程

1. 每組 5 分鐘彩排。
2. 老師檢查 demo 流程是否太依賴運氣。
3. 補齊 GitHub / 程式碼 / BOM / 接線圖 / 操作說明。
4. 錄製備用 demo 影片。

### 最低交付

- 展示簡報。
- 接線圖。
- 操作說明。
- 1 分鐘備用展示影片。

## 第 18 週：Demo Day

### 主題

展示、同儕觀摩、反思。

### 課堂流程

1. 每組 6-8 分鐘展示。
2. 2 分鐘 Q&A。
3. 同儕互評。
4. 繳交最終文件。
5. 課程回顧：從材料包到 IoT 系統。

### 最終交付

- 可運作原型。
- 程式碼。
- 接線圖。
- BOM 與成本。
- Dashboard 截圖。
- Demo 影片。
- 反思報告。

## 老師的課堂帶法建議

### 每週固定節奏

| 時段 | 做什麼 |
|---|---|
| 前 20 分鐘 | 概念圖解與本週目標 |
| 20-50 分鐘 | 老師 live demo |
| 50-110 分鐘 | 學生分組實作 |
| 110-130 分鐘 | 各組 checkpoint |
| 最後 10 分鐘 | lab notebook 與下週準備 |

### 每週固定 checkpoint

- 今天資料從哪裡來？
- ESP32-S3 讀到什麼？
- 系統如何傳資料？
- dashboard 或使用者看到什麼？
- 什麼情況會失敗？
- 失敗時怎麼知道？

### 硬體弱的學生如何降級

- 伺服閘門做不出來：先用 LED 表示開門 / 關門。
- 超音波不穩：先用按鈕模擬入口有車。
- OpenCV 不準：先用固定 ROI 與人工校正，不追求 AI。
- Dashboard 來不及：先用本機網頁或終端機表格。
- MQTT 卡住：先用 HTTP，期末再換 MQTT。

### 強的學生如何加深

- MQTT topic 設計。
- 多車位、多裝置。
- 資料庫與歷史紀錄。
- 預約、收費、權限。
- ArUco / QR 定位。
- 自走車或夾娃娃機機構。
- ROS 2 概念展示或 Gazebo 模擬。

## 我會特別提醒學生的紅線

- 不把 5V 訊號直接接 ESP32-S3 GPIO。
- 不讓伺服馬達從 3.3V 腳取電。
- 不帶電亂插拔。
- 不把線路弄成看不懂又沒有拍照紀錄。
- 不做未告知的人臉辨識或監控。
- 不做武器化、攻擊、干擾、投放等危險設計。
