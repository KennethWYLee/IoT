# 教師用 18 週完整課堂教材：UCI 4WD 版

本文件以每週 150-165 分鐘設計。共同平台為 ESP32-S3、UCI K-4 4WD、L298N 與智慧停車場。學生不用裁切或鑽孔底板，課堂重點放在安全接線、四輪差速、校正、狀態機、IoT 資料流與測試證據。

教師於 2026-11-01 至 2026-11-07 出國參加研討會，2026-11-04 改為非同步期中證據包；實車挑戰於 2026-11-11 進行。

## 全學期固定節奏

| 時間 | 活動 | 產出 |

每組每週 Lab Notebook 必須包含目標、接線或資料流圖、成功證據、錯誤與修正、AI 使用紀錄、下週第一件事。

## Week 4-5：智慧停車場最低規格

場地在第 4 週先用 UCI 4WD 實際外形或同尺寸紙模型驗證，不先憑想像決定格位。全班使用相同起點、格位尺寸、邊界寬度與重置程序。

最低事件格式：

```json
{
  "event_type": "collision",
  "time_ms": 15230,
  "zone": "left_boundary",
  "count": 1,
  "result": "running"
}
```

場地至少支援 `reset`、`start`、`collision`、`parked`、`finish`。如果感測器不足，可以用微動開關或按鈕先完成可靠的一區偵測，再把多區域當挑戰任務；不能用人工按鈕冒充自動碰撞偵測。

## Week 6：UCI 4WD 上電順序

1. 不裝電池，先完成機構組裝與四顆馬達標記：LF、LR、RF、RR。
2. 萬用電表確認電池盒極性與 LM2596 輸出，調到 5V 後才接 ESP32-S3。
3. 架空底盤，每次只測一顆馬達的正反轉。
4. 左前與左後組成左輪組，右前與右後組成右輪組。
5. 左輪組接 L298N channel A，右輪組接 channel B。
6. 確認馬達電源與 ESP32-S3 共地。
7. 落地前先測 `stop()`；任何發熱、焦味、重開機立即斷電。

本週不追求跑動，只收「四輪方向正確」及「停止有效」的證據。四馬達並聯可能讓 L298N 發熱，課堂避免長時間堵轉；若底盤卡住應立即停止。

## Week 7：差速控制與三種轉向

學生建立以下 API：

```text
stop()
forward(left_pwm, right_pwm)
backward(left_pwm, right_pwm)
curve_left(direction, pwm, ratio)
curve_right(direction, pwm, ratio)
spin_left(pwm)
spin_right(pwm)
```

學生必須實測並比較：同方向不同 PWM 的弧形轉彎、一側停止的單側樞軸、左右輪反向的原地旋轉。原地旋轉是 UCI 4WD 的正常能力，不扣分；但應記錄較大的電流、輪胎打滑、L298N 發熱與角度誤差。期中允許自由組合三種運動原語。

直行校正固定跑 100 cm 三次，記錄左 PWM、右 PWM、電池電壓、完成時間與終點偏移。只有在記錄證據後才修改 trim。

## Week 8：兩項任務與資格測試

### 倒車入格

```text
固定起點 -> 接近格位 -> 對正 -> 倒車進格 -> 完全停止 3 秒
```

### 側向停靠

```text
固定起點 -> 接近側向格 -> 轉向 / 後退組合 -> 車身進界 -> 完全停止 3 秒
```

每組必須在 10/28 前完成至少一項任務的 3 次錄影，並保留程式版本、參數表與 Serial log。這些材料用於 11/04 證據包；不能等到教師出國後才第一次接馬達。

## Week 9：11/04 非同步期中證據包

學生提交：

1. 10/28 前完成的 3 次測試影片。
2. 狀態機或 pseudo-code。
3. 左右輪方向、PWM、時間及電池狀態。
4. 三次成功、碰撞、偏移與時間比較。
5. 一次失敗的根因與下一版修改。
6. AI 建議、人工修改與實車驗證方式。

安全規則：本週不新增馬達接線、不改供電、不焊接、不進行無人監督的高速測試。需要硬體重接者寫入待辦，11/11 由教師檢查。

## Week 10：11/11 實車期中挑戰

每項任務 3 次。計分順序為成功次數、碰撞 / 越界、最終偏移、成功趟中位數時間。速度只占單項 10%，不能抵銷碰撞或人工介入。

期中 20 分由以下組成：

| 項目 | 分數 |
|---|---:|
| 11/04 非同步證據包 | 8 |
| 倒車入格 | 5 |
| 側向停靠 | 5 |
| 安全、重置與技術說明 | 2 |

## Week 11-17：從共同平台轉入自由專題

第 11 週把共同失敗分類成 power、wiring、motion、field、network、logic，再讓學生判斷期末是否需要 MQTT、WebSocket、dashboard 或手機視覺。停車場與 UCI 4WD 都可以沿用，但期末題目不限移動載具。

第 12 週只核准能在第 13 週跑通一條最薄端到端路徑的題目。第 13-16 週每週只有一個 gate，不追加大型新功能；第 17 週以前收齊主要成績證據。

## AI / Vibe Coding 規則

- 可以要求 LLM 產生狀態機、JSON、Web UI 或除錯假設。
- 不得在輪子著地時直接執行未讀過的馬達程式。
- 每次 AI 產生的 motor command 先架空輪測，再低 PWM 落地測。
- Notebook 必須記錄 prompt、採用內容、人工修改及實車證據。
- 評分看可解釋、可重現與安全，不看貼了多少 AI 程式碼。
