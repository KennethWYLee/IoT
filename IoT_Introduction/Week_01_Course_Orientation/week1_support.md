## 五、Full-stack IoT架構延伸說明

這門課的目標不是把一個感測器接上ESP32，也不是只做一個手機網頁。學生要
逐步完成一個Full-stack IoT系統：實體裝置能感測或回應，網路能傳送事件與
命令，後端能處理資料，Database能保存歷史，手機介面能協助使用者監看或操作。

```text
感測器／按鈕
  → ESP32-S3判斷狀態
  → 燈、聲音、舵機或其他實體輸出
  → Wi-Fi與HTTP／MQTT
  → 學生建立的Backend
  → Database與structured log
  → WebSocket
  → 手機可用介面

手機命令
  → Backend記錄與派送
  → ESP32-S3判斷是否接受
  → 執行、拒絕或timeout
  → 結果回到Backend、Database與手機
```

作品題目不限定為無人車。互動玩具、智慧教室、環境裝置、警報器、遊戲、
輔助裝置、移動平台或其他合理題目都可以，但必須具備可說明的使用情境、
真實硬體行為及有用途的軟體。

完成課程後，學生應能：

1. 分辨開發板、感測器、致動器、網路、Backend、Database與手機介面的責任。
2. 依電壓、邏輯準位、供電與共地原則安全接線，並使用萬用電表取得證據。
3. 將輸入、狀態、決策與輸出組成可重複操作且能安全停止的互動硬體。
4. 使用HTTP／MQTT、JSON與WebSocket串接裝置、後端、資料庫及手機介面。
5. 使用歷史資料與structured log解釋一次成功、失敗或修正。
6. 完成並說明一件具實體行為、軟體用途、安全機制與重建文件的IoT作品。

正式週次與成果定義見[18週課程規劃](../../docs/18_week_plan.md)。

## 六、重要評量週次說明

### 第一次個人筆試（Week 7）：硬體接線、電氣概念與安全

筆試只檢查Week 2～5的硬體基礎，包括ESP32-S3、GPIO、GND、3.3V／5V、
麵包板、共地、感測器、致動器、外部供電、安全停止及基本狀態判斷。全週
只進行個人作答，不安排新進度、硬體實作或小組活動。

### 第一次專題報告（Week 8）：題目與技術可行性

每組進行一次12～15分鐘的專題報告、硬體片段示範與問答。需要準備：

1. 作品使用者及核心操作。
2. 一個可運作的真實硬體片段。
3. 軟體要記錄什麼，或如何協助使用者操作。
4. 裝置、Backend、Database與手機的資料流。
5. 已有材料、預計加購材料、供電與驅動風險。
6. Week 12第二次專題報告可以檢查的最低成果。

完整成品不是Week 8要求。題目過大時，應刪減功能，保留可以測試的核心流程。

### 第二次專題報告（Week 12）：進度檢查、回饋與修正計畫

展示目前已完成的真實硬體與軟體片段，將裝置、Backend、Database、手機介面及
測試狀態分為已完成、部分完成與尚未開始，並以程式、log、資料或操作結果支持
判定。依目前問題與回饋提出具優先順序、負責人及完成條件的Week 13～14修正
計畫。Week 12保存可辨識的進度commit，之後仍可持續開發。

### 第二次個人筆試（Week 15）：網路通訊與軟硬整合架構

筆試檢查Week 6、Week 10～11及Week 13～14的整合概念，包括Wi-Fi、IP、HTTP、
JSON、WebSocket、MQTT、Backend、Database、手機前台、自動反應，以及sensor
signal、event、command、result與log如何跨層流動。全週只進行個人作答，不安排
新進度或實作。

### 第三次專題報告（Week 16～17）：期末作品

每組展示實體作品、手機前台、Backend、Database、structured log、測試與
限制。報告分兩週進行，每組依公布場次在Week 16或Week 17完成一次報告；
本項仍只計一次25%。每位成員須能說明一條資料／命令路徑，或一項硬體安全與錯誤處理。
