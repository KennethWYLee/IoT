# 08：作品設計與進度檢查

## 對應週次

Week 1 構想、Week 7 題目草案、Week 8 訪談、Week 13／15 進度檢查。

## 題目設計

- 使用者與情境、核心實體互動、軟體用途、最低可驗收成果。
- 實體輸入、實體輸出、ESP32、通訊、Backend、Database、手機資料流。
- BOM、既有設備、待補材料、供電／驅動／時間風險。

## Week 8 可行性訪談

每組 12-15 分鐘，帶可運作硬體片段、軟體用途、資料流、BOM、風險及
驗收條件。訪談決議必須轉成 Git 內的工作項目。

## Week 13 檢查一

一筆真實硬體資料必須進入 Backend 與 Database，並在手機出現；API、JSON、
topic 與欄位格式進入凍結。

## Week 15 檢查二

非主要開發者僅看介面提示，以手機完成核心流程三次；展示歷史資料、操作
log、錯誤狀態與一項測試前後的修正證據。

## 完成檢核

- [ ] 題目有明確使用者、價值與最低成果。
- [ ] 資料流、BOM、風險、驗收條件及分工完整。
- [ ] Week 13 真實資料端到端路徑通過。
- [ ] Week 15 非開發者三次操作與修正證據通過。
