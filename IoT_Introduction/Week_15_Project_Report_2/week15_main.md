# Week 15：第二次專題報告、修正、彩排與版本凍結

日期：2026-12-16

每組先展示一筆真實硬體資料從ESP32進入Backend與Database，最後在手機出現；
再由不是該組主要開發者的人，僅看介面提示，以手機完成核心流程三次。本週
要證明作品已端到端連通、可被使用、可追蹤，且已根據測試修正。本次報告
占學期成績15%。

## 必備展示

1. 真實硬體、Backend、Database與手機的同一筆事件路徑。
2. 三次手機核心流程。
3. 每次操作的command、result／ack或timeout。
4. Database歷史與structured log。
5. 一項測試前後的修正證據。

## 完成檢核

- [ ] 真實硬體資料端到端路徑可重複兩次。
- [ ] 三次流程的成功／失敗與時間都有紀錄。
- [ ] 測試者不需 IDE 或修改程式。
- [ ] 歷史、操作 log 及錯誤狀態可展示。
- [ ] 報告回饋已轉成明確修正清單，只修正缺陷或必要文件，不再增加功能。
- [ ] 依Week 16～17的報告時間限制完成兩次完整彩排。
- [ ] 固定展示commit／tag，並準備網路中斷時的核心互動與歷史資料備案。

## 報告後的版本凍結

完成必要修正後，固定commit／tag、接線圖、資料流、BOM、資料格式、啟動順序、
測試結果、AI驗證紀錄、已知限制與展示分工。除重大安全或阻斷性錯誤外，不再
新增功能；若必須修補，須留下變更原因與重測證據。
