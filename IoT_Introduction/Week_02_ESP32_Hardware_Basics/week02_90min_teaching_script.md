# Week 02：90 分鐘教師講稿與實作驗收

主題：ESP32-S3、程式上傳、Serial、安全接線與第一次輸入／輸出<br>
總課堂時間：165 分鐘<br>
教學：前 90 分鐘<br>
學生實作與驗收：後 75 分鐘；完成且驗收通過者可先離開

## 一、課前教師準備

### 軟體與檔案

- 公布本批 ESP32-S3 DevKitC-1 N16R8 的教師實測 board、flash、PSRAM 與
  upload 設定截圖。
- 準備可直接編譯的 Serial 範例，以及已填入「教師核對過 GPIO」的按鈕
  範例。不要要求學生根據網路圖片猜 GPIO。
- 準備一台已確認能上傳的教師筆電，供示範與問題比對。
- 開一個個別環境排錯區，處理未完成 Week 1 安裝作業的學生。

### 硬體分站

- 三組 ESP32-S3 工作站：每站一塊板、麵包板、資料線、按鈕與教師核准的
  低功率輸出，例如已實測的板載燈、RGB 模組或蜂鳴器。
- 萬用電表只有一支，設成輪流量測站，不讓所有組等待。
- 舵機、馬達、L298N 與外部電池本週不發放。

### 上課前板書

```text
今日資料流：按鈕 -> GPIO -> 程式判斷 -> Serial + 低功率輸出
安全順序：辨識 -> 畫圖 -> 斷電接線 -> 互查 -> 量測 -> 上電 -> 看 log
驗收完成 + 個別回答 + 斷電收納 = 可以先離開
```

## 二、0–90 分鐘教學講稿

### 0–5 分鐘：開場與規則

教師說明：

> 今天不花時間重新安裝 Arduino IDE。我們要學的是如何證明板子、程式與
> 接線安全而且正常。若安裝尚未完成，請進個別排錯區，不影響全班進度。

接著公布後 75 分鐘實作規則：完成全部任務並非「程式曾經亮過」；必須通過
教師驗收、每位組員個別回答、保存證據、斷電及收納，之後才可先離開。

提問學生：

- USB 插上去卻沒有 COM port，可能是哪些層次的問題？
- 程式編譯成功，能否證明硬體接線安全？為什麼？

### 5–15 分鐘：認識手上的 ESP32-S3

讓學生只觀察，不接線。請每組指出：

- USB 接頭、Boot、Reset、兩側排針、GND、3.3V 與 5V／VBUS 標示。
- 板身型號與購買規格：ESP32-S3 DevKitC-1 N16R8、向下 44 腳。
- 哪些資訊可由板身確認，哪些仍需官方 pinout 或教師實測設定。

教師強調：外觀相似不代表接腳、板載 LED、USB 或記憶體設定完全相同。
商品頁截圖只能用來領料辨識，不能作為接線權威。

### 15–27 分鐘：從程式到板子的完整流程

在板書畫出：

```text
原始碼 -> 編譯 -> 選擇 board -> 選擇 port -> upload -> reset
       -> setup() -> loop() -> Serial log -> 判斷目前狀態
```

逐一解釋：

- **Compile**：檢查語法並產生板子可執行的程式，不代表已寫入板子。
- **Board**：決定編譯目標與部分硬體設定。
- **Port**：決定要把程式送往哪個連接裝置。
- **Upload**：寫入板子；成功訊息與 Serial 程式輸出是兩種不同證據。
- **Serial baud rate**：程式與 Monitor 必須一致，否則可能看到亂碼。

請學生回答兩個情境：

1. 編譯成功但 upload 失敗，先檢查什麼？
2. upload 成功但沒有 Serial 文字，可能檢查什麼？

預期答案應涵蓋 port、資料線、Reset／Boot、baud rate、Monitor 是否開啟，
以及程式是否真的執行到 `Serial.begin()` 與輸出位置。

### 27–39 分鐘：教師示範上傳與 Serial

使用已驗證的教師設定，示範最小程式：

```cpp
unsigned long lastReportMs = 0;

void setup() {
  Serial.begin(115200);
  delay(500);
  Serial.println("boot: week02-ready version=1");
}

void loop() {
  unsigned long now = millis();
  if (now - lastReportMs >= 1000) {
    lastReportMs = now;
    Serial.printf("status: uptime_ms=%lu\n", now);
  }
}
```

示範時刻意指出四個證據：編譯完成、上傳完成、正確 port、可辨識版本的
Serial log。再把 `version=1` 改成 `version=2`，重新上傳，證明目前執行的是
新程式，不是剛好看到舊輸出。

### 39–51 分鐘：GPIO 與電壓安全

在板書分成三欄：

| 名稱 | 角色 | 本週底線 |
|---|---|---|
| GND | 電壓共同參考 | 有訊號往來時要確認是否需要共地 |
| 3.3V | ESP32 邏輯與低功率供電 | 不等於所有模組都可直接使用 |
| 5V／VBUS | USB 或板上電源路徑 | 不可直接當成 GPIO 訊號輸入 |
| GPIO | 邏輯輸入／輸出 | 不能拿來直接供馬達或舵機 |

教師說明：

> GPIO 是訊號腳，不是萬用電源。程式寫 HIGH 不代表它可以提供任何負載
> 需要的電流；5V 模組能上電，也不代表它的輸出訊號對 3.3V GPIO 安全。

情境題：舵機接 GPIO 後會動，所以這樣接是正確的嗎？答案必須指出即使
短暫動作，也可能過流、掉壓、重啟或損壞，不能以「有動」取代規格確認。

### 51–63 分鐘：麵包板、按鈕與 INPUT_PULLUP

用未上電麵包板示範內部連通方向。讓學生先猜哪些孔相通，再用通斷檔驗證。

說明四腳按鈕：同側通常原本相通，按下時才把兩側接通；仍要以實物通斷
量測確認。示範本週簡化接法：

```text
教師核准的輸入 GPIO -- 按鈕 -- GND
程式使用 INPUT_PULLUP
未按：HIGH
按下：LOW
```

強調「按下為 LOW」不是錯誤，而是內部上拉接法的結果。接線必須在 USB
拔除時完成；完成後由另一組先看接線圖與實物，再允許上電。

### 63–74 分鐘：萬用電表基本操作

只教本週需要的兩種模式：

1. **通斷檔**：電路斷電時確認麵包板、按鈕與線材是否相通。
2. **直流電壓檔**：上電後黑表筆對 GND，紅表筆量測指定測試點。

本週不操作電流檔。教師示範若把表筆插錯孔、量程選錯或在帶電時使用通斷
檔，可能得到錯誤結果甚至造成危險。萬用電表站採輪替方式，每組只完成指定
的通斷與電壓證據，不必等待全班同時量測。

### 74–84 分鐘：按鈕控制輸出的完整示範

使用教師已核對的輸入及輸出 GPIO，展示：

```text
按下按鈕
-> digitalRead() 得到 LOW
-> 程式判斷 pressed=true
-> Serial 印出 event=button_changed
-> 教師核准的低功率輸出改變
```

第一次只跑基本版本；再示範快速按壓可能產生彈跳，告訴學生 Week 3 才會
正式處理去抖與資料品質。今天的重點是完整、安全、可說明的輸入輸出路徑。

故意拔掉一條訊號線，問學生應先看哪個證據。要求回答順序包含：斷電、看
接線、通斷量測、重新上電、看 Serial，而不是直接換所有零件。

### 84–90 分鐘：發布實作任務與驗收標準

教師逐項說明後 75 分鐘任務，確認學生知道「每位組員都要回答」：

- A：上傳 Serial 程式並修改版本字串。
- B：完成按鈕 `INPUT_PULLUP` 接線與事件 log。
- C：按鈕控制教師核准輸出，連續測試五次。
- D：在萬用電表站完成一次通斷及一次直流電壓量測。
- E：保存程式、接線圖、GPIO 表、照片／短片及 log。

最後提醒：若接線未互查、證據不完整或只由一名組員回答，即使裝置會動，
仍不能提前離開。

## 三、90–165 分鐘學生實作

### 任務 A：環境與上傳證據

1. 選擇教師公布的 board profile 與自己的 port。
2. 上傳 Serial 範例。
3. 修改版本字串、再次上傳並保存新 log。

### 任務 B：斷電接線與互查

1. 畫 GPIO 接線表。
2. 拔除 USB 後接按鈕及教師核准輸出。
3. 和另一組交換接線圖；對方簽名確認後才上電。

### 任務 C：輸入輸出測試

1. 按鈕按下與放開都要有 Serial event。
2. 輸出狀態和按鈕一致。
3. 連續操作五次，記錄成功次數及一個限制。

### 任務 D：萬用電表輪站

1. 斷電量測按鈕未按及按下時的通斷。
2. 上電後量測教師指定的 GND 對 3.3V 測試點。
3. 寫下檔位、表筆位置與實測值，不只拍表面數字。

## 四、提前離開驗收表

完成後舉手，由教師或助教依序簽核：

- [ ] 每位組員能選出正確 board 與 port，並指出自己的上傳證據。
- [ ] Serial log 有組別、版本與可辨識的事件。
- [ ] 接線圖、GPIO 表及跨組上電前互查完成。
- [ ] 按鈕控制輸出連續五次，結果與 log 一致。
- [ ] 通斷及直流電壓量測有數值、檔位與測試點。
- [ ] 隨機抽問一題，每位組員都能用自己的話回答。
- [ ] 程式與證據已保存／提交。
- [ ] USB 與外部電源已拔除，零件清點、線材及桌面已復原。

全部通過後，教師記錄完成時間，該組可以先離開。未完成者持續實作至下課；
如果是環境問題，必須至少留下錯誤證據與下一步，不能用借用他人電腦取代
自己的環境準備。

## 五、個別口頭題庫

每位學生隨機回答一題：

1. Compile 成功與 Upload 成功有何不同？
2. 為什麼只有充電功能的 USB 線無法上傳？
3. 為什麼按鈕使用 `INPUT_PULLUP` 時，按下通常讀到 LOW？
4. 為什麼未確認的 5V 訊號不能直接進 ESP32 GPIO？
5. 共地的用途是什麼？
6. 為什麼 GPIO 不能直接供電給舵機或馬達？
7. 上傳成功但 Serial 沒輸出，你會依序檢查什麼？
8. 通斷檔與直流電壓檔分別在什麼狀態下使用？
9. 為什麼「亮過一次」不足以證明系統完成？
10. 程式、接線及 log 中，哪一項證據能證明目前執行的是你的新版本？
