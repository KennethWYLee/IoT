## A．按按鈕，手機看見事件
**作品**：用 ESP32 的兩顆按鈕與 RGB 做低功率網路示範，筆電接收、保存資料，手機即時顯示。

**特色**：筆電的後端（Backend）是接收事件與管理命令的程式；資料庫保存歷史，WebSocket 是保持連線、推送更新的通道。第二顆按鈕是 STOP，不是遊戲 Finish。

> 改線前斷電，只接已確認相容的低功率零件，不接舵機或高功率負載。只用允許的區域網路，不公開服務；密碼與操作金鑰不得進入程式庫、截圖或作答紙。

### 預期結果
| 操作 | 應有的反應 |
|---|---|
| 先由筆電送測試事件，不接 ESP32 | 後端接受並保存，網頁能查到；這不是實機測試 |
| 實體 START | 裝置 active（啟動）、RGB 綠色、手機新增事件 |
| 實體 STOP | 裝置 error（停止鎖定）、RGB 紅色；網路可用時另回報事件 |
| 手機不重新整理 | 仍能收到新的事件 |

**驗證方法**：先確認筆電資料接收，再接 ESP32 與手機。選自己的裝置代號，展示一次實體操作、電腦紀錄與手機同一筆事件。程式測試與實物結果分開標示。

## B．手機送命令，裝置回報結果
**作品**：在同一系統用手機 start、stop、reset 控制 RGB，能查到每一筆命令的結果。

**特色**：每筆命令有 command_id，用來把請求與回報對在一起；requested 表示已提出，accepted 表示裝置收到，done 表示程式完成，rejected 表示拒絕，timeout 表示期限內未確認結果。

### 預期結果
| 操作 | 應有的反應 |
|---|---|
| idle（待機、藍色）送 start | active、綠色，同一命令最後 done |
| 送 stop | error、紅色，同一命令最後 done |
| error 時送 start | rejected，不變綠 |
| STOP 按住時送 reset | rejected，保持停止 |
| 放開 STOP、排除原因後送 reset | idle、藍色；新 start 才啟動 |
| 重送仍保存在裝置近期紀錄中的同一 ID | 只重送原結果，不再執行動作 |

**驗證方法**：依表操作，追蹤同一 command_id 的狀態，另外目視核對 RGB。近期紀錄限同次開機最近八筆，不能宣稱重啟後仍永不重做。

### Q2．手機 timeout，能確定 RGB 沒變嗎？
紙上假設裝置已完成變色，但回報在途中遺失，其餘路徑正常。解釋手機能確定什麼、還缺什麼證據，以及為何直接換新 ID 再送可能重做。

## C．啟動中不接受另一筆 start
**作品**：替 B 加上狀態判斷，已啟動時拒絕另一個新 ID 的 start，不重做啟動事件。

**特色**：只加這條規則，保留停止、reset、error 拒絕及同 ID 重送的行為。

### 預期結果與驗證
| 開始條件與操作 | 應有的結果 |
|---|---|
| idle，送新 start | accepted → done，進 active |
| active，送另一新 ID 的 start | accepted → rejected，理由為已啟動；不新增 remote_start |
| 重送仍在近期紀錄中的已完成 ID | 回原結果，不重新執行 |
| error 送 start、STOP 按住時 reset | 沿用原來拒絕規則 |

**驗證方法**：從 idle 完成一次正常啟動，再送另一筆 start，展示兩個不同 ID 的不同結果與實物。用 stop、reset 確認仍可正常恢復。

## D．即時畫面與歷史查詢
**作品**：用同一系統的兩個手機頁籤，比較不刷新收到的新事件與刷新後讀回的歷史。

**特色**：兩頁選同一裝置。一頁保持前景接收即時更新；另一頁之後重新整理，查資料庫中同一筆事件。

**預期結果**：兩頁能找到相同事件 ID 與內容；重新整理不應再產生一筆新的實體事件。後端停止時不能取得新資料，舊畫面可以仍在。

**驗證方法**：送一次事件，依序觀察即時頁與查詢頁；展示相同 ID，不以手機顯示時鐘剛好一致作判準。

## 用四種故障檢查同一作品
每次只改一項，完成後恢復正常設定並重測一筆事件。不操作其他組的裝置或服務。

| 測試 | 預期結果與驗證 |
|---|---|
| 手機使用不存在的裝置代號 | 本組 ESP32 不會取得命令；查看它停在哪個狀態，再改回 |
| 裝置把目的位址設為自己的 127.0.0.1 | 事件不會送到筆電；還原後確認可送達 |
| 停止本組後端 | 實體 STOP 仍在 ESP32 本機處理；網路事件送達失敗不能阻止本機停止 |
| 傳送未知命令 blink-forever | 命令最終 rejected，不啟動 RGB；JSON 或權限錯誤須分開辨認 |

實體 STOP 不依賴後端成功，但網路請求可能暫時阻塞程式；量測或由影片估計按下到變色的時間，不宣稱是即時急停。後端恢復後，STOP 按住仍不得 reset，放開且排除原因才恢復。
