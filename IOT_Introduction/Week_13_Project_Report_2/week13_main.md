# Week 13：第二次專題報告—進度檢查、回饋與修正計畫

日期：2026-12-02

## Unit Overview

### 教學目標

完成本次專題報告後，學生應能：

1. 以可重現的實作證據（implementation evidence），將各主要系統部分區分為已完成、部分完成與尚未開始。
2. 展示一條可重複的實體操作或整合系統流程（integrated system path），區分真實運作、模擬資料（mock data）及只有介面呈現的證據。
3. 從可觀察行為、資料或紀錄（log）辨認目前問題或風險，說明其對專題的影響。
4. 將回饋轉為有優先順序的修正計畫（revision plan），為每項選定行動列出負責人、完成條件與重測方法（retest method）。

### 教學內容

本次專題報告檢查目前實作，而非要求已修飾完成的最終成品。學生會以正在展示的版本為依據，對照硬體行為（hardware behavior）、裝置通訊（device communication）、後端（backend）、資料庫（database）、行動介面（mobile interface）、測試及文件的證據。未完成工作與尚未解決的風險必須如實呈現，並將報告回饋轉為第14、15週可執行、範圍明確且可驗證的開發計畫（development plan）。

每組說明目前完成、部分完成及尚未開始的功能，並以真實硬體行為、程式、資料、
log或操作結果支持判定。尚未完成的功能可以誠實標示，不得以mock或投影片冒充
實作完成。本週只追蹤進度、取得回饋並建立修正計畫，Week 14～14仍可持續開發。
本次報告占學期成績15%。

## 必備展示

1. 一項目前可重複操作的真實硬體或軟硬整合片段。
2. 裝置、Backend、Database、手機介面與測試的進度矩陣。
3. 支持目前進度判定的程式、資料、log或操作結果。
4. 至少一項尚未解決的問題或風險，以及可觀察證據。
5. Week 14～14的修正計畫，包括優先順序、負責人與完成條件。

## 完成檢核

- [ ] 至少一項真實硬體或軟硬整合片段可重複展示。
- [ ] 所有主要系統部分已標示為完成、部分完成或尚未開始。
- [ ] 每項宣稱完成的內容都有程式、資料、log或操作結果支持。
- [ ] 至少一項目前問題或風險有具體證據。
- [ ] 報告回饋已轉成具有優先順序、負責人及完成條件的修正清單。
- [ ] 保存可辨識的Week 13進度commit或tag，並使文件對應目前展示版本。
- [ ] Week 14～14預計完成的工作及重測方式已記錄。

## 報告後的進度追蹤

保存本次展示的commit或tag、接線圖、資料流、BOM、資料格式、啟動順序、測試
結果、AI驗證紀錄及已知限制。這個版本只用來記錄Week 13進度，不限制後續開發。
Week 14～14的手機前台、自動反應與復原內容應使用後續commit保存；每次修改都須
留下原因、完成條件與重測證據。
