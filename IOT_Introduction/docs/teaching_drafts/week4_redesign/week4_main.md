## Week 4：環境顯示與警報分析
本週做四件作品：**環境顯示器 → 超標提示器 → 警報紀錄器 → 電腦分析結果顯示**。每件可選 OLED 或電腦顯示。Q1～Q3 的文字可看 Arduino IDE 的 Serial Monitor；Q4 連接電腦工具後，在工具看裝置回傳，不能同時開 Serial Monitor。

每週從空麵包板開始。本堂改線先拔除全部電源；下課保存檔案、斷電、拆線。可查資料或使用 AI，但作品與紀錄須在自己的設備上驗證。

<aside class="safety">模組供電與訊號須相容本板 3.3 V。環境變化示範由教師先核對感測器規格；液體、蒸氣及凝結水不得接觸電路，不用火或直接熱風吹感測器。</aside>

### Q1．桌上環境顯示器
**作品用途：**在一個畫面看到光線讀值、溫度與相對濕度。相對濕度表示空氣中的水蒸氣相對於當時溫度下飽和程度的比例，以 % 表示。

**預期畫面示例：**RAW 是光敏訊號電壓經 ESP32 轉成的整數；T 是攝氏溫度，RH 是相對濕度。以下不是本組實測值。
<pre class="screen">RAW:420
T:25.0 C
RH:50.0 %</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 開機，等到有效讀值 | 三種資料有名稱，溫濕度有單位 |
| 遮住光敏，再移開 | RAW 有反應；溫濕度不必跟著光線改變 |
| 尚未讀到或讀取失敗 | 顯示 -- 或失敗提示，不用 0 冒充結果 |

**完成後回答：你實際量到的溫度與相對濕度是多少？**

## Q2．環境超標提示器
**作品用途：**不必自己一直比數字，畫面直接指出溫度或濕度哪一項超過設定。

本題先用 **28°C、65%RH** 作練習門檻，不是健康或設備安全標準。只有「大於」門檻才算超標；等於未超標。任一項超過時顯示 ALERT（警報），兩項都未超過時顯示 NORMAL（正常）。

**預期畫面示例：**溫度超過、濕度未超過。
<pre class="screen">T:30.0C RH:60.0%
LIMIT T:28.0C
LIMIT RH:65.0%
TEMP:HIGH
RH:NORMAL
ALERT</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 比較當次讀值與門檻 | 各項 HIGH／NORMAL 和比較結果一致 |
| 展示正常及至少一項超標 | 總狀態分別為 NORMAL、ALERT |
| 沒有有效讀值 | 顯示等待或失敗，不能當作 NORMAL |

可先把門檻改到目前讀值的另一側，重新上傳，核對程式判斷。這是在測試判斷規則，**不代表環境真的改變**。

要觀察真實變化，使用教師已確認的示範方式，等感測器的新讀值。若沒有超過門檻，如實記錄，不把示例當實測。

**完成後回答：選一次提示結果，寫出讀值、門檻與哪一項超標。**

## Q3．環境警報紀錄器
**作品用途：**除了當下提醒，還知道警報發生幾次、累計多久，以及使用者是否看過警報。電腦保留紀錄，之後可以回頭查。

**預期畫面示例：**ACK:YES 表示已按按鈕確認；COUNT 是警報次數，TIME 是程式處於警報狀態的累計秒數。以下數字只示意畫面。
<pre class="screen">T:29.0C RH:55.0%
ALERT ACK:YES
COUNT:3
TIME:80s</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 第一次讀到超標 | 進入警報，次數增加 1，開始累計時間 |
| 持續超標，再按一下按鈕 | 次數不連續增加；標成已確認，仍是警報 |
| 讀值恢復正常 | 警報解除，累計時間停止增加 |
| 再次超標 | 次數再加 1，新警報尚未確認 |
| 讀取失敗 | 顯示 UNKNOWN（目前無法判斷），保留紀錄；不冒充恢復正常 |

按鈕只表示「我看到了」，不清除次數、不讓超標變正常。長按不重複確認。讀取失敗期間不繼續累計警報時間；若之後仍超標，延續原警報，不重複計次。

門檻沿用 Q2，一次紀錄中保持不變。示範至少完成一次「進入警報 → 確認 → 恢復正常」。可以再製造一次警報，檢查計次；實際未出現的情況不可填成已完成。

## CSV 紀錄與警報分析報告
Q3 同時透過 USB 把資料送到電腦。使用本週提供的收資料工具，不要求自行寫電腦端程式。

**CSV 是能用試算表打開的文字資料檔**：每列是一筆紀錄，每欄是時間、讀值或狀態。報告由這份實際紀錄產生，不是另填一份假想資料。

### 預期成果
1. 按「開始紀錄」後，開始一份新紀錄，裝置次數、累計時間重新計算。
2. 電腦持續收到溫度、濕度、狀態及按鈕確認；OLED 版同時保留裝置畫面。
3. 按「停止紀錄」，可下載 CSV 和一份警報分析報告。
4. 報告列出觀察時間、門檻、警報次數、累計警報時間、最長一次警報及讀取失敗筆數，並呈現溫濕度隨時間的圖。

| 你怎麼驗證 | 應有的結果 |
|---|---|
| 打開 CSV | 每筆有時間；失敗的讀值留空，狀態仍保留 |
| 對照最後裝置畫面與報告 | 次數與累計時間一致 |
| 回看一次警報與按鈕操作 | 能找到警報開始、確認、恢復的紀錄 |
| USB 中途斷開或裝置重啟 | 標示紀錄不完整，不把缺資料當正常 |

報告只整理這次收到的資料；不判斷健康風險，也不能保證量到兩次讀取間的每一瞬間。若結束時警報尚未解除，最長時間須註明包含尚未結束的警報。

**完成後回答：展示作品、CSV 與報告。指出一次警報何時開始、是否確認、何時恢復；沒恢復就如實說明。**

## Q4．電腦分析結果顯示
**作品用途：**電腦保存警報資料、即時分析，再將結果送回 ESP32 顯示。使用本週提供的電腦工具。

**操作：**先連接裝置、選擇電腦的保存資料夾，再按「開始新紀錄」。每次建立不同檔名的 CSV，不覆蓋上一份。實體按鈕仍只負責確認警報。

**預期畫面示例：**電腦算出次數、累計時間及最長一次時間。以下不是本組實測值。
<pre class="screen">COUNT:2
TOTAL:10.0s
MAX:7.5s
PC:LIVE</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 按「開始新紀錄」 | 出現新的 CSV；本次三項統計歸零 |
| 新警報、確認、恢復 | CSV 增加紀錄；電腦與裝置顯示相同統計 |
| 持續同一次警報 | 次數不反覆增加；累計與最長時間隨新資料更新 |
| 停止，再開始新紀錄 | 保留舊檔，新檔與統計重新開始 |
| 沒有新的電腦分析結果 | 顯示等待或逾時，不能把舊統計當最新結果 |

使用 OLED 就核對螢幕；沒有 OLED，就核對工具的「裝置回傳」區，這裡要顯示 ESP32 收到分析後回傳的結果，不是只看電腦自己算出的數字。每筆新資料才更新，不要求每毫秒變動。

**完成後回答：展示兩次紀錄的 CSV，並指出電腦與裝置相同的三項統計。**沒有警報可如實展示 0，不編造事件；檔案寫入失敗或連線中斷須顯示錯誤。
<div class="write-space small"></div>

完成後保存檔案、關閉連線，拔除全部電源，確認斷電後拆線收納。
