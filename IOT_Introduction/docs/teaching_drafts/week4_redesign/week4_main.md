## Week 4：把環境資料用起來
本週有三件用途不同的小作品，使用已學元件加上 DHT 溫濕度感測器。每件可選 **OLED 或 Serial Monitor** 顯示；後者是 Arduino IDE 顯示開發板文字的視窗。不要求每件作品都接上所有元件。

每週從空麵包板開始；同堂可保留已確認的接線，改線前拔除全部電源。下課先保存程式、斷電，再拆線收好。可查資料或使用 AI，成果要在自己的設備上驗證。

<aside class="safety">DHT 的供電、訊號與 GND 依本片資料確認。不要用火、熱風或水製造溫濕度變化。</aside>

### Q1．桌上環境顯示器
**作品用途：**不用猜測周圍狀況，直接看到光線讀值、溫度與相對濕度。

**預期畫面：**以下數字只是示例；顯示本組量到的結果。RAW 是 ESP32 將光敏訊號電壓轉成的整數，T 是攝氏溫度，RH 是相對濕度。
<pre class="screen">RAW:420
T:25.0 C
RH:50.0 %</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 開機並等約 3 秒 | 三種資料有名稱；溫度、濕度有單位 |
| 遮住光敏再移開 | RAW 有反應，溫濕度不必同時跟著變 |
| 尚未讀到或讀取失敗 | 溫濕度顯示 -- 或明確提示，不用 0 冒充結果 |

**完成後回答：你使用哪種顯示方式？實際溫度與相對濕度是多少？**

## Q2．環境超標提示器
**作品用途：**使用者不必一直盯著數字，畫面直接告訴他哪一項超過自己設定的門檻。

本題先用 **28°C、65%RH** 當門檻。這只是練習設定，不是健康或設備安全標準。只有「大於」門檻才算超標；等於仍是正常。溫度與濕度各自判斷，不能只顯示其中一項。

**預期畫面示例：**30°C 超過 28°C；60%RH 沒超過 65%RH。
<pre class="screen">T:30.0C RH:60.0%
LIMIT T:28.0C
LIMIT RH:65.0%
TEMP:HIGH
RH:NORMAL
ALERT</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 比較實測值與設定門檻 | 各項 NORMAL／HIGH 與比較結果一致 |
| 將門檻調到目前讀值的另一側，再測 | 畫面依新門檻改變；不必加熱或弄濕感測器 |
| 尚未取得有效溫濕度 | 顯示等待／失敗，不能判成 NORMAL |

至少展示「都正常」和「有一項超標」兩種狀態。紀錄當時設定及實際讀值，不抄上面的示例。

**完成後回答：選一次超標結果，寫出實測值、門檻，以及畫面顯示哪一項超標。**

## Q3．兩個位置的環境比較器
**作品用途：**比較 A、B 兩個位置的溫度與濕度，不必靠記憶猜哪裡比較高。

在 A 位置等讀值更新後按一下，保存 A。移到 B，等讀值更新後再按一下，保存 B。畫面保留兩筆並顯示 **B − A**。不要求兩處一定不同；同一環境也可用來測試流程。

**預期畫面示例：**B 比 A 高 1°C，相對濕度高 3 個百分點。百分點是兩個百分比直接相減，例如 53% − 50% = 3 個百分點；畫面用 pp 表示。
<pre class="screen">NOW 26.0C 53.0%
A:25.0C 50.0%
B:26.0C 53.0%
dT:+1.0C
dRH:+3.0pp
NEXT:A</pre>

| 你怎麼驗證 | 作品應有的結果 |
|---|---|
| 每次先放開，再按一下 | 依序保存 A、B；長按約 3 秒不重複保存 |
| A、B 保存後，現在的讀值改變 | A、B 與差值保持不變 |
| 第三次按下 | 開始新一組 A，清空舊 B 與差值 |
| 溫濕度無有效讀值時按下 | 不保存、不前進，已有 A／B 不被覆蓋 |

**完成後回答：你保存的 A、B 溫度是多少？B − A 是多少？正負號表示什麼？**

## Q4．看見數字，就代表剛量到嗎？
某次 DHT 成功量到 25.0°C。下一次讀取失敗，畫面仍顯示 25.0°C，而且沒有標示「上次成功值」。

**使用者可能誤會什麼？你會如何修改顯示，讓他分得清「目前沒有新結果」與「真的量到 25.0°C」？**
