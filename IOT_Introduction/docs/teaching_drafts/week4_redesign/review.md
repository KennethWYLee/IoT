## 建議 120 分鐘使用方式

此為備課估時，不是已觀察到的學生完成時間。

| 時間 | 活動 |
|---|---|
| 0–10 分 | 說明作品、斷電整理、核對器材 |
| 10–25 分 | 電阻量測及量程判讀 |
| 25–50 分 | DHT 開檔、程式庫、接線、讀值與資訊流 |
| 50–65 分 | f/r、資料品質與五題討論；含短休息 |
| 65–85 分 | 加 KY、第一輪雙感測器與資料時間 |
| 85–105 分 | 第二輪穩定事件、個別故障與恢復 |
| 105–115 分 | 已確認時做短音及 q/u；否則保留無聲作品並檢查事件紀錄 |
| 115–120 分 | 最後練習、保存與斷電收尾 |

完整程式附錄供開檔與查找，不逐頁朗讀；色環容差可課後補充。程式庫宜課前裝好但保留教材步驟。若接線／DHT 排錯佔用時間，先保住無聲整合與資料品質，不刪除安全停止步驟硬趕聲音。

## 課前尚未完成的硬體條件

**第一優先：DHT11 實物確認與試讀。** 現有紀錄只有照片，不能替代可操作腳序。完成條件如下，需由教師核對實物並記錄，不由本次文件建置聲稱完成。

1. 斷電後拍清楚三針標示與正反面，確認 VCC／DATA／GND；線色不當依據。
2. 根據該模組來源／電路確認 3.3 V 供電及 DATA 拉高不超出 ESP32 邏輯輸入限值；無資料時不改接 5 V 硬試。
3. 核對實際板型、可用且不衝突的 GPIO、USB／IDE 設定、供電能力；填課堂共用的明確腳位圖與設定。`PIN_DHT` 不由助理猜為 5、6 或 18。
4. 實測 DHT 單獨讀取、f/r 與 KY 整合；記錄正常及失敗嘗試、電壓、GPIO、版本、照片與實際觀察，再將適用接法補回教材。
5. 本批其他組器材也需確認適用，不把 BOARD-T01 的局部結果提升為全班通過。

其他尚未解決的條件：

- HW-508 歷史只有 T01 經 1 kΩ、2000 Hz／200 ms 有聲回報；未量電流、真實聲長或確認 Reset 安靜。canonical Week 4 是 120 ms，兩者不混為同一測試。p27–29 是條件完成後的操作，不是本批已核准接線圖。
- KY 最新實物的方向與較早紀錄不同，尚未完成本輪基準；本教材不混合不同輪資料，也不把遮光固定寫成變大。
- A830L 原廠完整手冊仍缺；2k 與二極體功能不靠照片猜。Fluke 文件只支持一般斷電／表筆原則，不證明 A830L 的畫面和旋鈕功能。
- 本次沒有連接、閃寫、通電或操作硬體；不更改 hardware_state.md 的實測狀態。

課堂不是逐組等待教師准許後才執行；上述是課前統一備妥的條件。沒有準備好的硬體項目，明確縮限到可完成的活動，不能寫成學生已完成整套實作。

## 檢查與限制

- 2026-09-16 建置 47 頁 A4；DOM 逐頁檢查超出邊界、頁尾間距、圖片與內部參照。
- 程式附錄由兩份原始 `.ino` 自動嵌入，HTML 抽取後與原檔逐字比對；來源、照片、builder、PDF SHA-256 存在 build_manifest.json。
- `verify.py` 對 47 頁做文字與尺寸檢查並全部轉 PNG。兩組題目／解答相鄰檢查通過，獨立檢查容差、475 ms、分類表、事件序列 0/1/1/2/2、麵包板節點。
- 執行既有 `verify_week4_host.py`，有效準位模式 96 項主機斷言通過；加 `--tone` 模式 102 項通過。這是 canonical 程式加替代 I/O，涵蓋品質、順序、邊界、候選、事件、靜音及恢復；不證明實機電位、聲長、排針或電流。MSVC 有常數條件 C4127 警告，沒有編譯／執行失敗。
- 本次未重新做 Arduino 目標編譯，因為程式未改動；不將主機成功寫成 Arduino 重新編譯或實機通過。
- 視覺檢查全部 47 頁縮圖，另檢查 DHT／雙感測器接線、照片、品質答案、時間圖與長程式頁。最後修正後已重新輸出並檢查；品質答案另以 Poppler 渲染確認。最小頁尾間距 114.45 px，未發現超出邊界、缺字、未解析標記或圖片載入失敗。
- 原正式 Week 4 notebook 的既有唯讀檢查通過：18 cells、32 圖、23 本地連結／錨點、兩支來源一致程式與數值檢查。`git diff --stat` 為空，確認未修改已追蹤的正式檔。
- canonical 程式的設計限制原樣說明：DHT 失敗不封鎖 KY 事件；整體基準範圍內、兩段基準間的 raw 仍可能分類；取樣不是精準排程。同步 DHT 程式庫讀取會占用時間；不能稱所有讀取完全非阻塞。
