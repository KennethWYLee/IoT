## Week 4：環境顯示與警報分析
依序完成**顯示、提示、紀錄、分析回傳**。選 OLED 小螢幕或電腦 Serial Monitor 文字視窗，可查資料及使用 AI；用自己的設備驗證。

<aside class="safety">從空麵包板開始。接線、改線前拔除 USB 與其他電源。只用供電與訊號相容 3.3 V 的模組；液體、蒸氣及凝結水不接觸電路，不用火或直接熱風吹感測器。</aside>

### Q1．桌上環境顯示器
**做出什麼：**光敏提供訊號電壓，DHT11 感測器提供空氣溫濕度。ESP32 程式讀取及判斷，再送到所選畫面顯示；螢幕本身不量測。

**完成畫面示例：**以下是示例，不必做出相同數字。
<pre class="screen">RAW:420
T:25.0 C
RH:50.0 %</pre>

RAW 是 ESP32 將光敏訊號電壓轉成的整數；T 是攝氏溫度。RH 是相對濕度，表示空氣中的水蒸氣相對於當時溫度下飽和程度的比例，以 % 表示。

### 展示作品
| 操作或情況 | 必須看見的結果 |
|---|---|
| 開機，等待約 5 秒 | 三種讀值有名稱；T、RH 由等待變成數字與單位 |
| 遮住光敏，再移開 | RAW 隨光線變化；溫濕度不必跟著變化 |
| 尚未讀到或讀取失敗 | 顯示 -- 或失敗提示，不用 0 冒充結果 |

**回答：你實際量到的溫度與相對濕度是多少？**

## Q2．環境超標提示器
**做出什麼：**用 DHT11 的溫濕度判斷是否超標。畫面要分別指出溫度、濕度的狀態，再顯示總結果。本題不用光敏判斷。

練習門檻為 **28°C、65%RH**，不是健康或設備安全標準。讀值**大於**門檻才超標，等於未超標。任一項超標時顯示 ALERT（警報）；兩項都未超標時顯示 NORMAL（正常）。

**完成畫面示例：**這組示例只有溫度超標。
<pre class="screen">T:30.0C RH:60.0%
LIMIT T:28.0C
LIMIT RH:65.0%
TEMP:HIGH
RH:NORMAL
ALERT</pre>

### 展示作品
| 操作或情況 | 必須看見的結果 |
|---|---|
| 展示一次兩項都未超標 | 兩項為 NORMAL，總結果也為 NORMAL |
| 展示一次至少一項超標 | 超標項為 HIGH，總結果為 ALERT |
| 尚未讀到或讀取失敗 | 顯示等待或失敗，不判成 NORMAL |

可用不同練習門檻驗證判斷，須標示當次設定；改門檻不代表環境真的改變。觀察真實環境變化時，使用教師已確認的示範方式。

**回答：選一次提示結果，寫出當次讀值、門檻與超標項目。**

## Q3．環境警報紀錄器
**做出什麼：**用 DHT11 判斷警報，顯示發生幾次、總共持續幾秒。按鈕表示「我看到了這次警報」。

一次警報從讀到超標開始，到讀到正常結束。持續超標只算一次；恢復正常後再次超標，才算新的一次。門檻沿用 Q2，一次測試中不更改。

**完成畫面示例：**COUNT 是次數，TIME 是累計秒數；ACK:YES 表示已按鈕確認。以下只是示例。
<pre class="screen">T:29.0C RH:55.0%
ALERT ACK:YES
COUNT:1
TIME:8.0s</pre>

### 展示作品
| 操作順序 | 必須看見的結果 |
|---|---|
| 第一次超標，持續觀察 | COUNT 加 1，TIME 增加；不一直新增次數 |
| 警報中按一下按鈕 | ACK 變 YES；仍是 ALERT，時間繼續增加 |
| 等讀值恢復正常 | 警報解除，TIME 停止增加；統計保留 |

按鈕不解除警報、不清除統計，長按不重複確認。若讀取失敗，顯示 UNKNOWN（目前無法判斷）並暫停計時；讀取恢復後仍超標，延續原警報。按 RST 或重新上電才歸零。

**回答：展示警報開始、按鈕確認與正常恢復；寫出最後的次數與累計秒數。**

## Q4．電腦分析結果顯示
**做出什麼：**ESP32 讀光敏、DHT11 並判斷兩種警報；電腦工具經 USB 收資料、保存及分析，再經 USB 回傳統計顯示。實體按鈕只確認警報；電腦「開始新紀錄」才建立資料檔。

預設光線 RAW **大於 3000** 時觸發光線警報；溫度**大於 28°C** 時觸發溫度警報。等於未超標。若本組光線讀值無法跨過 3000，可在開始紀錄前選能跨過的分界，標示當次設定；濕度只顯示與紀錄。這些是練習門檻，不是安全標準。

**兩組分開計算：**COUNT 是警報次數；TOTAL 是累計秒數；MAX 是其中一次最長的秒數。L 表示光線，T 表示溫度。以下只是完成畫面示例。
<pre class="screen">L COUNT:2
L TOTAL:7.5s
L MAX:5.0s
T COUNT:1
T TOTAL:7.5s
T MAX:7.5s</pre>

### 展示作品
| 操作或情況 | 必須看見的結果 |
|---|---|
| 開始一次新紀錄 | 新資料檔、兩組統計重新開始 |
| 改變光線，使 RAW 跨過分界，再回到原側 | 光線警報開始／恢復；溫度仍依自己的讀值判斷 |
| 警報時按實體按鈕 | 確認當時尚未確認的警報；不停止計時、不清零 |
| 查看電腦與裝置 | 兩邊的光線、溫度統計對得上 |
| 尚無新分析或回傳逾時 | 裝置顯示等待或逾時，不把舊統計當最新結果 |

OLED 版在 OLED 看結果；電腦顯示版在工具「裝置回傳」看 ESP32 回覆，不能只看電腦自己算出的統計。

## Q4．資料檔與警報分析報告
**CSV 是可用試算表開啟的文字資料檔。**每列是一筆紀錄，每欄放時間、讀值或狀態。每次新紀錄建立不同檔名，不覆蓋上一份。

**報告包含什麼：**光線、溫度各自的警報次數、累計與最長時間，以及光線、溫度、濕度的圖。報告整理收到的資料，不判斷健康風險。

### 展示作品
| 要展示的成果 | 如何確認完成 |
|---|---|
| 兩次紀錄的 CSV | 檔名不同，兩份都保留；每筆有時間與狀態 |
| 其中一份的報告 | 有兩組警報統計和三種讀值的圖 |
| 同一份紀錄的最後結果 | 電腦、報告、裝置的兩組統計一致 |
| 警報事件 | 找到開始、按鈕確認與恢復；未恢復如實標示 |

失敗讀值留空；若 USB 中斷或裝置重啟，應標示紀錄不完整，不能把缺少的資料當正常。這些是異常時應有的行為，不要求帶電拔感測器來製造失敗。

| 溫度 |  |  |  |

沒有警報就填 0，不編造事件。警報還沒恢復也如實標示；統計的是程式警報狀態時間，不是兩次讀取之間每一瞬間的環境狀態。

完成後保存檔案、關閉連線，拔除全部電源，確認斷電後拆線收納。
