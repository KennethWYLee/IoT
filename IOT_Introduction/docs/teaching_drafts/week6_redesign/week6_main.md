## 讓數字變成會動的指針

> 前幾週把資料顯示在螢幕上。這週讓同一個數字，也能用位置表示。

{{diagram:goal}}

先在電腦輸入 `0`，再輸入 `1`。確認供電與接線後，觀察指針是否移到下一格。

今天做的是**輕量紙指針**，不是推門、吊重物或讓車輪一直轉。位置由你輸入，不是自動偵測人數。

### 今天的完成條件

- 說得出電源線、訊號線、GND 各接哪裡。
- 讓數字、OLED 與紙指針表達同一個值。
- 能中止操作，分清「停訊號」與「切電源」。

## 先讓電腦顯示一個結果

1. 電池盒 OFF，取出至少一顆電池；拔 USB。
2. 暫時移除所有杜邦線與模組，只留下 ESP32 開發板。
3. 開啟本週的「數字預覽」完整程式，連接 Week 2 已用過的板背 `COM` 接頭。其他板型以實物接頭為準。
4. 在 Arduino IDE 選擇 Week 2 已成功使用的板型、Port，按勾號編譯，再按右箭頭上傳。
5. 開啟右上角 Serial Monitor（序列監控視窗），選 `115200`。
6. 輸入 `3`，按 Enter。再分別輸入 `0`、`6`。

<aside>此程式只做數字運算，不設定 GPIO，也不輸出舵機控制訊號。尚未完成 Week 2 上傳者，先回到該週 IDE 設定頁，不猜 Port。</aside>

預期格式如下，這是**示例輸出，不是實機量測**：

```text
mode=preview count=3 angle_example=90
servo_connected=false
```

實際程式將上面欄位印在同一行。輸入框請一次送一個數字；`10` 是兩個字元，不是「第十格」。

## 0～6，不是 0～6 度

這個數字預覽假設：第 0 格對應 60，第 6 格對應 120。兩端之間有 **6 個間隔**。

```text
每格差 = (120 - 60) / 6 = 10
示例角度 = 60 + 格數 × 10
```

| 格數 count | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 示例角度 | 60 | 70 | 80 | 90 | 100 | 110 | 120 |

{{diagram:information}}

這叫做**映射**：把一組數字對應到另一組數字。現在只在記憶體中算出結果，沒有舵機動作。

<aside class="safety">60～120 只是本頁算式的示例，不是你手上舵機的安全角度。後面的實機程式必須使用課前確認的數值。</aside>

先預測輸入 `4` 會出現什麼，再執行檢查。輸入 `9` 應被拒絕，不擴大範圍。

## 舵機的三條線各做一件事

{{diagram:threewires}}

| 功能 | 白話意思 | 接到哪裡 |
|---|---|---|
| V+ | 提供工作電力 | 外部降壓輸出正極 |
| GND | 電力回路與訊號參考 | 外部輸出負極，並與 ESP32 GND 共接 |
| signal | 接收位置指令 | 已確認可用的 GPIO |

GPIO 是「告訴它要去哪裡」，不是提供轉動所需的全部電力。**不要把 V+ 接到 GPIO 或 3V3。**

先把實物的三個功能指出來，才開始接線。照片上的顏色只是辨識線的輔助；功能以確切版本文件與已核對的接頭方向為準。

## 先不要接舵機

{{photo:BuckConverter_3.jpg|58|教師既有照片：VIN 接電池，VOUT 尚未接舵機。IN 顯示不是輸出電壓。}}

全班先在**斷電狀態**一起找四個端子：`VIN+`、`VIN−`、`VOUT+`、`VOUT−`。

1. 電池盒 OFF，取出至少一顆電池。
2. 電池正線固定到 VIN+，負線固定到 VIN−。
3. VOUT 暫時不接舵機；正、負導體各自絕緣，不互碰。
4. 輕拉確認固定，沒有裸銅鬚跨到旁邊端子。

端子若不匹配，先停在辨認步驟，不把裸線塞入杜邦母頭，也不靠膠帶維持鬆脫接點。

<aside>降壓模組把較高電壓降下來，不是升壓器，也不是電池。顯示數字正常，不代表已能帶動舵機。</aside>

## 黑筆接哪裡？紅筆接哪裡？

{{diagram:meter}}

1. 黑筆插 `COM`；紅筆插 `VΩmA`，不插 `10A`。
2. A830L 轉到直流電壓 **20 V** 檔，不是電阻或通斷檔。
3. 開關 OFF 時固定黑筆在 VOUT−、紅筆在 VOUT+。避免兩支金屬筆尖互碰。
4. 裝回同種類、同狀態的電池；接點固定後 ON，讀取數字、正負號與 V 單位。
5. OFF，再移開表筆或改線。

需要調整輸出時，舵機仍不接。只用絕緣工具操作調整螺絲，小幅調整，並用電表對照；改接或固定測點先 OFF。

<aside class="safety">這是在量兩點的電壓差，不是在量電流。不可把電表切到電流檔，再跨接正負極。</aside>

## 空載讀值不能保證動作時一樣

課程既有紀錄如下，三個值來自不同測點或儀表：

| 既有回報 | 它表示什麼 | 不能直接推論什麼 |
|---|---|---|
| 四顆 1.5 V AA，量到 6.6 V | 電池組當時的電壓 | 舵機可直接接 6.6 V |
| 模組 OUT 顯示 4.85 V | 模組自己的顯示值 | 電表也一定顯示 4.85 V |
| 電表跨 VOUT 量到 4.76 V | 當時尚未接舵機的讀值 | 動作時供電已通過 |

**空載**：沒有供應舵機工作電流。**帶載**：舵機已接上並在工作。

兩者都用 V 表示電壓。帶載可能掉壓；慢速電表也可能漏掉短暫變化。4.76 V 不因「很接近 4.8」就自動合格，須對照確切舵機規格、量測不確定度與停止條件。

現行課程方案是四顆 1.5 V AA 加降壓模組；不能直接換成四顆 1.2 V eneloop，再假設仍能穩定降到 5 V。替換電池是另一個需要確認的供電方案。

### 程式中的 false 與 −1 是什麼？

`false` 表示「尚未確認可以啟用」；`-1` 表示「尚未填入設定」。它們刻意讓程式先不操作舵機。

若顯示 `status=blocked reason=profile_missing`，意思是設定還缺，不是舵機壞掉。**不要只把所有 false 改成 true 來消除訊息。**

本課先前提出 GPIO7 作 signal 的候選接法，但沒有實機通過紀錄。本頁不把候選值當作全班已驗證配置。

## 沿用 Week 2 的按鈕

所有電源斷開，舵機先不接。選按鈕的兩組不同接點；用斷電通斷檔確認「放開不通、按下通」。

{{diagram:stopwire}}

| 這條線 | 從哪裡 | 到哪裡 |
|---|---|---|
| 地線 | ESP32 GND | 麵包板 a3 |
| STOP 訊號 | 設定表上的 STOP GPIO | a20 |
| 按鈕第一組 | 按鈕一組接點 | b20 |
| 按鈕第二組 | 按鈕另一組接點 | b25 |
| 回地 | c25 | c3 |

b20／b25 是用導線連接的節點，**不是把按鈕四腳硬跨五列**。a20、b20 同組相通；b25、c25 相通；第 20 與 25 列本來不通。

先核對麵包板的孔組；板子放旁邊用線連接，避免板體擋住插孔。

## 為什麼按下會讀到 LOW？

{{diagram:pullup}}

程式設定 `INPUT_PULLUP`：啟用晶片內部的上拉電阻。

- 放開按鈕：通往 GND 的路斷開，輸入通常讀 HIGH。
- 按下按鈕：GPIO 經按鈕連到 GND，讀 LOW。
- 上拉電阻限制這條回路的電流，因此不是把 3V3 電源直接用線短接到 GND。

這裡的 STOP GPIO 是**輸入**，不能沿用 Week 3 的輸出高低電壓程式。先移除舊線，換上本週程式，再按本週圖接線。

STOP 是軟體讀取的停止鍵，不是工業安全急停，也不是電池開關。程式失效時不能保證它仍有效。

## 舵機接線分兩部分

USB 拔除，電池 OFF 並取出至少一顆。確認接頭方向，不按線色猜功能。

{{diagram:power}}

| 線路 | 來源 → 目的 |
|---|---|
| 工作電力正極 | VOUT+ → 安全端子 → 舵機 V+ |
| 工作電力負極 | 舵機 GND → 安全端子 → VOUT− |
| 共同參考 | ESP32 GND（a3）→ 外部負極端子 |
| 位置指令 | 設定表的 signal GPIO → 舵機 signal |

舵機工作電流不經麵包板的低功率電源列。端子與導線須符合負載需求，接頭固定不能鬆脫。

<aside class="safety">外部正極不接 ESP32 的 GPIO、3V3、5Vin 或 USB VBUS。只將指定的 GND 接在一起，不是把兩個電源正極相接。</aside>

## 先看停止鍵的紀錄

本頁須已有完整、相符的設定。舵機外部電源仍 OFF；接上板子的 USB。

| 操作 | 預期狀態或紀錄 |
|---|---|
| 開機，不按鍵 | `DISARMED`，尚未啟用控制脈波 |
| 按住 STOP | `ABORTED`、`physical_stop` |
| 按住時送 `a` | 不能啟用 |
| 放開，稍等後送 `c` | 清除可清除的原因，仍不動 |
| 再送 `z` | 回到 `DISARMED`，仍不動 |

看到 `DISARMED`，白話是「尚未準備控制」；`ABORTED` 是「已中止，需要處理原因」。

這段只檢查按鈕與程式狀態，不代表舵機轉動正常。**尚未確認工作電源 OFF 時接收訊號是否相容，不能送 a。**

STOP 若沒反應，先斷電檢查腳位、按鈕接點及目前上傳的程式，不進入下一步。

## 先不裝紙指針

本頁僅適用已完成課前供電、接頭、脈寬及上電順序驗證的器材。固定舵機本體，轉軸周圍沒有手、導線或其他物件。

1. 外部電源 OFF，USB 已接，狀態 `DISARMED`，STOP 放開。
2. 在**已確認允許先有 signal、再有工作電源**的配置，送 `a`。程式準備第 0 格的命令。
3. 確認紀錄後，把外部電源 ON；觀察起始位置。
4. 平穩後才送 `1`，和上一個命令至少隔 1 秒。初次只走已確認的小範圍。
5. 正常結束時送 `q`，外部 OFF，再拔 USB。

`a` 的紀錄只是操作者表示「我已關外部電源」，**程式沒有量到開關是否真的 OFF**。

<aside class="safety">這個先後順序不是所有舵機都適用。若可能由 signal 回灌、啟動亂動或規格未明，保持斷電；不要自行改上電順序試運氣。課前須先解決，不能只靠程式保護旗標。</aside>

有卡住、抖動、發熱、異味或板子重啟，立即外部 OFF，再拔 USB。不等待 30 秒、不提高電壓、不強扳轉軸。

## 哪些是程式說的？哪些是你看到的？

| 記錄項目 | 怎麼取得 | 可以說什麼 |
|---|---|---|
| `count=1` | Serial | 程式接受第 1 格 |
| `angle_command` | Serial | 程式送出的角度命令 |
| 軸是否移動、是否平穩 | 觀察／影片 | 該次實際可見反應 |
| 舵機 V+ 對 GND 電壓 | 電表並聯量測 | 當時量到的電壓 |

帶載量測先 OFF、拔 USB，固定安全測點，再按已確認流程重新操作。不要在移動機構旁臨時用筆尖找裸線。

電表不能證明沒有短暫掉壓；程式也沒有角度或電流感測。`position_measured=false` 就是「沒有量到實際位置」。

如果 Serial 有紀錄但軸沒動，先停止，再分開查電源、signal、共同地與機構。不用反覆送指令來掩蓋問題。

<!-- page: pulses | 看到動作後：訊號在做什麼 -->
## GPIO 不是一直送出「90」

{{diagram:pulse}}

圖中高電位維持 1.5 ms，整段每 20 ms 重複一次。這叫**脈波**；高電位持續的時間叫**脈寬**。

| 程式動作 | 它做的事 | 沒有做的事 |
|---|---|---|
| `attach()` | 啟動控制通道 | 不保證機構沒有碰撞 |
| `write(angle)` | 按設定換算脈波 | 不量測真實角度 |
| `detach()` | 停止控制脈波 | 不切斷外部電源 |

20 ms 相當於每秒 50 次；1.5 ms 等於 1500 µs。這是時間示意，不是本班所有舵機共同安全設定。

一般三線舵機會在內部控制位置，但本程式沒有讀回實際角度；library 的 `read()` 也不能當作外接角度感測器。

## 兩邊需要同一個電壓參考

{{diagram:reference}}

Week 3 用電表看「紅筆電壓減黑筆電壓」。舵機判讀 signal 時，也要相對自己的 GND 看高低。

ESP32 說「相對我的 GND 是 HIGH」，不等於隔離的另一個電路自然看到相同電壓。因此按接線圖，把指定 GND 連起來。

### 兩條路徑分開追

**工作電流：** 外部 VOUT+ → 舵機內部電路與馬達 → 舵機 GND → VOUT− → 電源內部回路。

**資訊：** Serial 命令 → ESP32 計算 → signal 的脈波 → 舵機內部控制 → 軸移動。signal 相對共同 GND 判讀。

共地不代表把舵機工作電流繞進板上的細訊號線。也不要帶電拔 GND 來展示錯誤。

## 先對位置，再固定紙片

{{photo:SG90_1.jpg|55|課程既有配件照片。白色舵盤裝在軸上，紙片固定在舵盤上，不把軸黏死。}}

1. 在已測通的小範圍內，命令回到第 0 格，記下方向。
2. 外部 OFF、拔 USB，才安裝配套舵盤與短、輕、無尖角紙指針。
3. 本體固定在底板；不靠手壓住、不把膠灌進軸或齒輪。
4. 按相同安全流程重新啟用，逐格觀察，在紙盤標出**實際指向位置**。
5. 每格穩定後才下一格，最後試 `4 → 3` 的回退。

第 0 格不必朝正上方，也不代表實際 0 度。不要為了對印好的刻度，強行扳軸或增加行程。

七格全範圍未通過前，只標已確認的小範圍；不因講義有數字 6 就直接跳到端點。

## 同一個數字，兩種呈現

先外部 OFF、取出至少一顆電池、拔 USB。沿用 Week 5 已確認的 OLED，不重新猜控制器。

| OLED 功能腳 | 接到哪裡 |
|---|---|
| GND | b3，與 a3 的 ESP32 GND 同組 |
| VDD／VCC | b6，與 a6 的 ESP32 3V3 同組 |
| SDA | Week 5 已確認的 SDA GPIO |
| SCK／SCL | Week 5 已確認的 SCL GPIO |

SDA、SCL、signal、STOP 四個 GPIO 不得重複。T01 曾用 SDA8／SCL9、0x3C 與 SSD1315 相容配置有畫面；不是所有同名螢幕都能直接套用。

1. 電源斷開，移除外接線後上傳新設定：`WITH_OLED=true`，填入 OLED 設定。
2. 拔 USB，恢復接線，重新核對電源正極分開。
3. 按既有安全順序啟用，送 `0`、`1`，確認數字與指針。

OLED 顯示 `NO SENSE` 是提醒「沒有量到真實位置」，不是一定壞了。ACK 回應也不證明每個像素都正確。

## 共用 count，分開檢查結果

{{diagram:shared}}

先說出你預期的結果，再送出一個命令：

| 命令 | OLED 預期 | 指針應觀察什麼 |

## 三種停止，並不一樣

| 做法 | 程式狀態 | 外部電源 | 下一步 |
|---|---|---|---|
| 送 `q` | DISARMED，停止脈波 | 可能仍 ON | 外部 OFF，再拔 USB |
| 按 STOP 或送 `x` | ABORTED，鎖定 | 可能仍 ON | 外部 OFF，查原因 |
| 外部 OFF，再拔 USB | 兩種供電關閉 | OFF | 才能改線或拆指針 |

### 中止後，不會自己繼續

解除原因、外部 OFF、STOP 放開，稍等後依序送：

```text
c → 清除可清除的原因
z → 回到 DISARMED，還沒有重新動作
a → 依已驗證上電流程重新準備第 0 格
```

按住 STOP 時，c／z／a 不能讓舵機重新啟用。`a` 每次重設 count 為 0，不是接續上次值。

停止控制訊號可能失去保持力，但不能保證立刻停止所有機械運動。軟體按鈕不是取代可操作的電源開關。

## 逾時與故障，不靠拔線測

一次只做一項。使用已確認的小範圍與輕指針；不故意卡住舵機，也不帶電拔 OLED。

| 測試 | 怎麼做 | 預期證據 |
|---|---|---|
| 太快輸入 | 兩個數字相隔不到 1 秒 | 第二個拒絕，count 不變 |
| 最長啟用時間 | 從 a 起算，不延長測試 | 到 30 秒中止，`arm_session_timeout` |
| 軟體故障 | 送 f | `injected_fault`，停止脈波並鎖定 |
| STOP 持續按住 | 按住時嘗試 a | 仍中止，不恢復 |

30 秒是本課程式的限制，不是舵機一定能安全工作的承諾；有異常應立刻關電源。

顯示通訊阻塞、函式執行及迴圈排程都會影響停止反應。本程式在顯示前後檢查，不能宣稱毫秒級最壞停止時間已經實測。

RST 不能當作恢復捷徑。重啟行為留到課前專門驗證；課堂先外部 OFF 再重啟，不在帶載時試未知瞬態。

## 這些紀錄能證明什麼？

以下都是教學情境，不是今天的實測結果。先寫答案，再翻頁。

1. 數字預覽用 60～120 對應 0～6。輸入 4，示例角度是多少？需要舵機嗎？
2. 外部電源 OFF，但 Serial 印出 `signal_attached=true`，可以說馬達已轉動嗎？
3. 按 STOP 後顯示 ABORTED，能立即拔線嗎？還缺哪兩個動作？

5. OLED 顯示 COUNT 4/6，紙指針卻在第 3 格。你會記錄什麼？第一個操作是什麼？

## +、− 與上下限

完成原有 a 啟用流程。每次有效命令相隔至少 1 秒，先預測 count，再觀察。

| 起始值 | 送出的命令 | 預期 count |
|---|---|---|
| 0 | `+` | 1 |
| 1 | `+` | 2 |
| 2 | `-` | 1 |
| 0 | `-` | 仍 0，拒絕低於下限 |
| 6 | `+` | 仍 6，拒絕超過上限 |

表格最後兩列是不同的起始情境，不是從上一列直接接續。

每次核對：Serial count、OLED count、紙盤位置。記錄「命令角度」，不要填成「實測角度」。

中止後再送 + 不應加分也不應繼續動作。恢復並重新 a 會歸零；這份程式沒有永久保存計數。

同一秒貼上很多 + 不是速度測試：超過接受頻率的命令會被丟棄，不會排隊等它慢慢轉。

## 原本的安全限制繼續用

程式原本接受 0～6。新版本先把 +／− 換算為下一個數字，再交回原本的條件檢查。

```cpp
if (c == '+' || c == '-') {
  if (count == 6 && c == '+') {
    Serial.println("event_type=command_rejected reason=upper_limit");
    return;
  }
  if (count == 0 && c == '-') {
    Serial.println("event_type=command_rejected reason=lower_limit");
    return;
  }
  c = char('0' + count + (c == '+' ? 1 : -1));
}
```

`'0' + 數字` 把 0～6 轉回字元，沿用原本 handleCommand 的後續判斷。這段本身沒有直接呼叫 `pointer.write()`。

只有狀態允許、STOP 放開、沒有故障、距前次至少一秒，才接受下一個 count。拒絕的操作不修改 count。

## 每次改兩格，但不超出 0～6

使用「加減計數指針」程式，只改 +／− 的計數換算。不要修改供電設定、實體角度端點、STOP、1 秒間隔或 30 秒上限。

### 新規則

- `+`：加 2，但最多 6。
- `-`：減 2，但最少 0。
- 到上限再加、到下限再減，仍維持原本的拒絕紀錄。
- 先在紙上算或主機假輸入測試；完整安全行程已驗證才做實物。

### 要留下的證據

1. 從 0 依序 `+ + + + - - - -`，每步預期值。
2. 先送 `3`，再 `+ + -`，每步預期值。
3. ABORTED 時按 +，計數與脈波應有何結果？
4. 程式只改哪一段？為什麼不需要擴大舵機角度？

## 只改下一個數字的計算

在前面的 +／− 處理區塊，保留兩個上下限拒絕條件，把最後的 `c = char(...)` 一行換成：

```cpp
int next = count + (c == '+' ? 2 : -2);
if (next > 6) next = 6;
if (next < 0) next = 0;
c = char('0' + next);
```

| 測試 | 預期結果（每次間隔符合要求） |
|---|---|
| 從 0：+ + + + | 2、4、6、6；第 4 次拒絕 |
| 接著：− − − − | 4、2、0、0；第 4 次拒絕 |
| 先指定 3：+ + − | 5、6、4 |
| ABORTED 時 + | count 不變，不重新啟用脈波 |

仍然只傳 0～6 給原有換算函式，因此不必改角度端點。完整程式仍由原有條件決定是否接受，不直接繞過 `applyCount()` 的呼叫條件。

這些是參考預期與主機測試目標，不是舵機實測紀錄。改動後重新編譯，依相同斷電與上傳流程處理。
