# 教材修訂準則

## 2026-09-30：依 Week3 整理可沿用的 Main、Ans、program 做法

本節整理教師對 Week3 的最新決定，先用於 Week4；未授權時不自動改其他週。沿用的是學生閱讀與實作方式，不是 Week3 的光敏、按鈕或 OLED 題目。以下與早期修訂紀錄不同時，以本節及教師後續決定為準。

### Main：學生拿到就知道要完成什麼

- Main 是考卷。先介紹本週作品之間的關係，再按原教學順序出題，不為湊 A、B、C 而新增作品。
- 每個實作題依序寫「作品是什麼、特色、預期結果、如何驗證、需要回答的問題」，保留足夠作答空間。先給可觀察的完成條件，不先列 GPIO、程式庫、接線步驟或解法。
- 紙上題提供必需的圖、數據、規則及名詞意義；不能要求學生猜「本課規則」。只看 Main 應能理解題意與完成條件，不代表未學過的學生不需教學就會實作。
- 實測題問學生實際讀到什麼，包含單位。假資料只用於指定的判讀或邊界測試，不能當作實測答案。
- 每題檢查一個主要能力。作品展示已可證明的結果，不另要求抄表、重寫規格、填影片位置或敘述無關的操作細節。手動操作不要求精確到毫秒；精確邊界由程式或紙上資料核對。
- 必要安全條件仍放在操作之前；危險反例限定紙上推演，不為使題目簡短而移除。

### Ans：先填完原卷，再逐題教

- 前段保留 Main 全部題目、順序、條件與格式，在原作答處標出答案。開放題給可接受的回答例；實測題標明以實測為準，不虛構讀值。作品規格頁保留，但不硬加書面問題。
- 所有題目結束後才開始詳解。按相同題序說明：準備與安全、開哪個程式、操作與接線、看見的結果、原理、必要排錯。
- 概念第一次需要理解時，先說它是什麼及在剛才作品中的用途，再舉例，最後說限制。不能用另一個陌生名詞代替解釋。
- 正常電流回路與資訊傳遞分開畫清楚，再只改一個元件、接點或程式設定比較。箭頭標明傳遞的是電流還是資料；公式定義符號並補足推導。
- 明說標字在哪個物件上，例如「電表上標示 COM 的插孔」「OLED 板上標示 SCK 的腳」，不用「紅筆插 10A」這種省略對象的說法。

### program：完整程式可找到，也知道啟動前缺什麼

- 使用每週現有 `programs` 資料夾；每支 Arduino 程式放同名子資料夾。維護來源、題目、檔名、必要設定與預期啟動訊息逐一對應。
- Ans 只保留解釋所需短片段，完整程式另開檔案。基本作品與延伸答案各自獨立，不把答案藏在基本程式的一個開關內。
- 未確認的硬體設定明列為待確認；說明如何辨認「設定未完成」與真正讀取失敗。不把保護旗標改為 true 就宣稱可接線使用。
- 雲端、本機來源與程式副本不同時先比較並備份，依教師指定版本同步，不讓打包覆蓋其修改。GitHub、雲端的發布範圍分別依當次授權。

### 套用到下一週前的檢查

1. 閱讀該週維護來源與器材紀錄，列出原有題目、作品和學習重點；不新增零件、功能、作業量或評分。
2. 先只讀 Main：能否指出每題要交什麼、需要哪些已給條件、怎樣判斷完成？刪除不能檢查額外能力的重複提問。
3. 逐題核對 Ans 前段是否保留原題，後段是否能找到操作與解釋；實作結果與參考程式必須一致。
4. 核對 program 來源、副本、檔名與設定；分開記錄紙上驗算、主機測試、ESP32 編譯及實體測試。
5. 重建 PDF、逐頁渲染查版面、核對頁碼及答案隔離。交付時說明已完成與尚待確認之處，不自動發布。

- 此輪 `programs` 與 Ans 維持 Git 忽略；沒有 commit、push 或雲端上傳。未來任何發布需依當次授權，不沿用較早的上傳要求。

## 2026-09-29：標字必須說清楚屬於哪個物件

教師要求清理 Week3 全文的省略描述。後續編修沿用此原則；本次實際修改範圍為 Week3 Main、Ans 及圖說，不代表其他週已重新檢查。

- 操作寫成「哪個物件的哪個部位，做什麼」：表筆插頭插進萬用電表插孔，金屬筆尖碰電路測點；插孔、旋鈕檔位、測點不能合成「紅筆 10A」之類短語。
- 實物標字保留原字，但附上位置與類型，例如「電表上標示 10A 的表筆插孔」「開發板上標示 COM 的 USB 接頭」「Arduino IDE 的 Port 連接埠選單」。同名標字出現在不同物件時，必須分清楚。
- 麵包板孔位、開發板 GPIO 編號、模組腳名、程式變數、畫面欄位與物理單位分開交代。表格可用標頭一次交代物件，不能讓學生猜 b6 是哪裡、115200 是哪個設定。
- 題目只補足辨認對象與作答條件，不因此加功能或洩漏解法。圖中保留短標字時，由同圖標題或圖說交代物件。
- 依閱讀順序檢查正文、表格、圖說、警告與程式旁解說；不以全文機械加長取代逐段判斷。既有程式識別字不為文字修訂任意改名。

## 今天確認的寫法

### 1. 直接寫內容，不解說教學安排

講義可以口語，也可以正式；重點是讓讀者直接理解情境、動作、結果及原因。

- 不寫「這一頁先不改程式」「下一頁再解釋」「現在不用理解」「做完再講」等安排說明。
- 不用句子反覆提醒學生目前正在讀哪一頁、老師打算何時講什麼。
- 接線、斷電、儲存、上傳等必要操作順序必須保留。刪除的是安排敘述，不是操作步驟。
- 故障處理、接線圖與完整程式的查找頁碼可以保留。

例如，將「先知道作品要做什麼；這一頁先不改程式，也不改接線」改為「用兩個按鈕記錄進出人數，滿 20 人時顯示 FULL」。

### 2. 不讓學生追蹤教材或程式的修訂歷史

- 不以「原版／新版」「舊教材」「五人版本」的比較解釋眼前任務。
- 需要辨認程式時，直接寫功能或實際檔名，例如 `counter_practice` 是雙按鈕計數器，`room_counter` 是房間人數計數器。
- 題目與預期結果只談該作品，不夾帶其他作品的上限或行為比較。
- 真正需要修改的程式值仍須寫清楚；20 人房間題完整解答使用 `MAX_COUNT = 20`。
- 板卡、軟體版本、USB 接頭及官方截圖與實際設定的差異屬於必要辨認資訊，不能一併刪掉。

例如，房間人數計數器的預期結果頁直接寫測試條件，不再寫「不是原版上限 99 的結果」。

### 3. 情境、預期結果與實作方法分清楚

- 練習題先交代角色、用途、限制及學生要完成的行為，不立即揭露改法。
- 預期結果完整列出每個連續操作，讓學生知道完成後應有什麼反應。
- 解答說明開哪個檔案、另存成什麼、改哪一段、如何上傳及核對；是否放在同一份講義依教師對該題的最新決定。
- 雙按鈕計數器先講完：操作、預期結果、測試、完整程式及原理都留在主教材第 25–32 頁。不能把它的程式穿插在下一個房間練習之後，也不能因分離房間題解答而移走計數器程式。
- 最新安排：基礎 counter_practice 只讀鍵、加減、印數字；不加去抖、單次按壓鎖定、雙鍵規則、上下限或事件格式。主教材第 33–34 頁整合「活動入場人數登記」的情境、簡短預期結果與觀察問題，要求 0～20、長按連加減及雙鍵暫停。負數、重啟與 loop 不另立講解專頁；精確計時表與實作細節留在補充，不列成主教材的額外規格。所有練習解答只在 week2Ans.pdf 第 1–8 頁。

### 4. 預期結果直接給出，不讓學生猜題意

- 計數器練習直接顯示預期數字與完整 Serial Monitor 訊息，不以「實際結果」空格取代答案範例。
- 20 人題列出前五次長按計數、後續固定間隔與到達 20 的時間，不讓學生猜長按速度。
- `FULL` 應在哪一步新增、減到 19 後不再新增，都要明確。
- 區分歷史訊息與目前狀態：畫面仍留著 `FULL`，不代表最新的人數仍是 5。
- 預期輸出、計算示例與實測資料要清楚區分，但不需要每段反覆插入製作或測試說明。測試細節留在維護紀錄。
- 此決定針對計數器教學，不代表刪除所有電表觀察欄或學生自行記錄的欄位。

### 5. 操作必須接得起來

- 不在組裝與上傳之前，就寫成要求學生立即試按的指令；作品介紹應寫「預期反應」。
- 每個操作交代目前條件、工具或檔案位置、具體動作、預期結果及不符時的查找方式。
- 一次只改有必要的項目，避免在多個設定之間來回切換。
- 基礎計數器只做數字加減與資訊流、電流說明；負數、長按、重啟、雙鍵、loop 與計時討論都屬練習，不放回基本教學。刪除「停在哪一步，就處理那一步」專頁與指向該頁的引用。

## 延續並重新核對的要求

### 6. 從零開始，完成操作後再解釋原理

- 不假設學生知道 IDE 設定、上傳 Serial 範例或「設為輸入腳」的意思。
- 安裝、開啟、選板型、選 Port、貼程式、儲存、上傳、開 Monitor 與預期訊息均須完整。
- 延續師生一起照講義操作、得到可觀察結果後再解釋原理的方式。
- 不加入「教師逐組檢查後才能繼續」的關卡。板型辨認、斷電與安全核對仍須在操作之前。

### 7. 圖要能回答具體問題

- 實物照片用來辨認板子、接頭與腳位；接線圖用來找兩端接點，不能互相取代。
- 電流路徑與資訊流分開畫、分開標示；資訊箭頭不是杜邦線。
- 清楚標出元件在哪裡。例如上拉電阻在 ESP32 晶片內，不在按鈕或麵包板內。
- GPIO4／GPIO5、GND 與麵包板孔位要在圖、表、文字與程式中一致。
- 不為後續章節預埋尚無用途的 TPO 標記。

### 8. 用同一個電路解釋電壓與電流

- 明確寫出 HIGH／LOW 是 GPIO 相對 GND 的電壓高低，不是電流大小。
- 回應「按下接通為何是 LOW」「放開是否電壓都留在板子」等提問，不能只給名詞。
- 解釋按下前後的電壓變化時，先對照接法：放開時通往 GND 的路斷開；按下時直接接到 GND。再回答「不是還接著 3.3V 嗎」：3.3V 一側隔著大電阻，GND 一側電阻幾乎為零。公式放在這段白話說明之後。
- 用 V = I × R 時，分清電阻兩端的電壓差與 GPIO 對 GND 的電壓差，定義 V、I、R 與單位。
- 圖中直接用中文標出比較位置：電阻左端與右端、GPIO4 與 GND。不要求初學者先記 V_R、V_GPIO 才能讀圖。
- 放開與按下沿用同一張電路及同一假設；30,000 Ω 是計算示例，不是宣稱實物精確阻值。
- 第 20–22 頁保留三頁圖解；依後續授權，第 23 頁另加「電阻換成導線」的兩張對照圖。按下情況須標明電源短路，不可保證 GPIO 固定為 0V，也不可列成實作步驟。

### 9. 保持版面與內容一致

- 每頁有明確主題；不用縮小字體把情境、全部結果與解答硬塞在一起。
- 短指令、成對訊息與相關操作避免被拆散；長程式提供可開啟的完整檔案。
- 學生頁尾只留課題與頁碼。草稿狀態、修訂沿革及測試報告留在 README 或維護紀錄。
- 保留已確認的語氣、配色、圖片與例子，不因單一批註重做整套版型。
