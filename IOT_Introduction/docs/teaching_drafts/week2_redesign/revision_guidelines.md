# Week 2 教材修正準則

整理日期：2026-09-21；2026-09-22 更新計數器與房間題要求。

適用範圍：Week 2 主教材及其維護來源。教師後續已要求 layout sample 取代正式 `week2_main.pdf`；現行主教材共 35 頁，練習解答放在本機 Week2 補充第 23–30 頁。本文件記錄教師確認的寫法，不新增作業或評量；其他週仍依各次授權範圍修改。

## 今天確認的寫法

### 1. 直接寫內容，不解說教學安排

講義可以口語，也可以正式；重點是讓讀者直接理解情境、動作、結果及原因。

- 不寫「這一頁先不改程式」「下一頁再解釋」「現在不用理解」「做完再講」等安排說明。
- 不用句子反覆提醒學生目前正在讀哪一頁、老師打算何時講什麼。
- 接線、斷電、儲存、上傳等必要操作順序必須保留。刪除的是安排敘述，不是操作步驟。
- 故障處理、接線圖與完整程式的查找頁碼可以保留。

例如，將「先知道作品要做什麼；這一頁先不改程式，也不改接線」改為「用兩個按鈕記錄進出人數，滿 20 人時顯示 FULL」。

### 2. 不讓學生追蹤教材或程式的修訂歷史

- 不以「原版／新版」「舊教材」「五人版本」的比較解釋眼前任務。
- 需要辨認程式時，直接寫功能或實際檔名，例如 `counter_practice` 是雙按鈕計數器，`room_counter` 是房間人數計數器。
- 題目與預期結果只談該作品，不夾帶其他作品的上限或行為比較。
- 真正需要修改的程式值仍須寫清楚；20 人房間題完整解答使用 `MAX_COUNT = 20`。
- 板卡、軟體版本、USB 接頭及官方截圖與實際設定的差異屬於必要辨認資訊，不能一併刪掉。

例如，房間人數計數器的預期結果頁直接寫測試條件，不再寫「不是原版上限 99 的結果」。

### 3. 情境、預期結果與實作方法分清楚

- 練習題先交代角色、用途、限制及學生要完成的行為，不立即揭露改法。
- 預期結果完整列出每個連續操作，讓學生知道完成後應有什麼反應。
- 解答說明開哪個檔案、另存成什麼、改哪一段、如何上傳及核對；是否放在同一份講義依教師對該題的最新決定。
- 雙按鈕計數器先講完：操作、預期結果、測試、完整程式及原理都留在主教材第 25–32 頁。不能把它的程式穿插在下一個房間練習之後，也不能因分離房間題解答而移走計數器程式。
- 最新安排：基礎 counter_practice 只讀鍵、加減、印數字；不加去抖、單次按壓鎖定、雙鍵規則、上下限或事件格式。主教材第 33–34 頁整合「活動入場人數登記」的情境、簡短預期結果與觀察問題，要求 0～20、長按連加減及雙鍵暫停。負數、重啟與 loop 不另立講解專頁；精確計時表與實作細節留在補充，不列成主教材的額外規格。所有練習解答只在補充第 23–30 頁。

### 4. 預期結果直接給出，不讓學生猜題意

- 計數器練習直接顯示預期數字與完整 Serial Monitor 訊息，不以「實際結果」空格取代答案範例。
- 20 人題列出前五次長按計數、後續固定間隔與到達 20 的時間，不讓學生猜長按速度。
- `FULL` 應在哪一步新增、減到 19 後不再新增，都要明確。
- 區分歷史訊息與目前狀態：畫面仍留著 `FULL`，不代表最新的人數仍是 5。
- 預期輸出、計算示例與實測資料要清楚區分，但不需要每段反覆插入製作或測試說明。測試細節留在維護紀錄。
- 此決定針對計數器教學，不代表刪除所有電表觀察欄或學生自行記錄的欄位。

### 5. 操作必須接得起來

- 不在組裝與上傳之前，就寫成要求學生立即試按的指令；作品介紹應寫「預期反應」。
- 每個操作交代目前條件、工具或檔案位置、具體動作、預期結果及不符時的查找方式。
- 一次只改有必要的項目，避免在多個設定之間來回切換。
- 基礎計數器只做數字加減與資訊流、電流說明；負數、長按、重啟、雙鍵、loop 與計時討論都屬練習，不放回基本教學。刪除「停在哪一步，就處理那一步」專頁與指向該頁的引用。

## 延續並重新核對的要求

### 6. 從零開始，完成操作後再解釋原理

- 不假設學生知道 IDE 設定、上傳 Serial 範例或「設為輸入腳」的意思。
- 安裝、開啟、選板型、選 Port、貼程式、儲存、上傳、開 Monitor 與預期訊息均須完整。
- 延續師生一起照講義操作、得到可觀察結果後再解釋原理的方式。
- 不加入「教師逐組檢查後才能繼續」的關卡。板型辨認、斷電與安全核對仍須在操作之前。

### 7. 圖要能回答具體問題

- 實物照片用來辨認板子、接頭與腳位；接線圖用來找兩端接點，不能互相取代。
- 電流路徑與資訊流分開畫、分開標示；資訊箭頭不是杜邦線。
- 清楚標出元件在哪裡。例如上拉電阻在 ESP32 晶片內，不在按鈕或麵包板內。
- GPIO4／GPIO5、GND 與麵包板孔位要在圖、表、文字與程式中一致。
- 不為後續章節預埋尚無用途的 TPO 標記。

### 8. 用同一個電路解釋電壓與電流

- 明確寫出 HIGH／LOW 是 GPIO 相對 GND 的電壓高低，不是電流大小。
- 回應「按下接通為何是 LOW」「放開是否電壓都留在板子」等提問，不能只給名詞。
- 解釋按下前後的電壓變化時，先對照接法：放開時通往 GND 的路斷開；按下時直接接到 GND。再回答「不是還接著 3.3V 嗎」：3.3V 一側隔著大電阻，GND 一側電阻幾乎為零。公式放在這段白話說明之後。
- 用 V = I × R 時，分清電阻兩端的電壓差與 GPIO 對 GND 的電壓差，定義 V、I、R 與單位。
- 圖中直接用中文標出比較位置：電阻左端與右端、GPIO4 與 GND。不要求初學者先記 V_R、V_GPIO 才能讀圖。
- 放開與按下沿用同一張電路及同一假設；30,000 Ω 是計算示例，不是宣稱實物精確阻值。
- 第 20–22 頁保留三頁圖解；依後續授權，第 23 頁另加「電阻換成導線」的兩張對照圖。按下情況須標明電源短路，不可保證 GPIO 固定為 0V，也不可列成實作步驟。

### 9. 保持版面與內容一致

- 每頁有明確主題；不用縮小字體把情境、全部結果與解答硬塞在一起。
- 短指令、成對訊息與相關操作避免被拆散；長程式提供可開啟的完整檔案。
- 學生頁尾只留課題與頁碼。草稿狀態、修訂沿革及測試報告留在 README 或維護紀錄。
- 保留已確認的語氣、配色、圖片與例子，不因單一批註重做整套版型。

## 後續修訂時的檢查

1. 先讀本準則及[README](README.md)，確認本次範圍，不沿用較早紀錄中已被取代的安排。
2. 修改維護來源，再產生 PDF；不直接修補 PDF。程式片段由 `.ino` 讀入。
3. 收到「這類都拿掉」時，檢查整份學生文字、標題、圖說與頁尾，不只刪批註的一句。
4. 逐項回看既有批註：GPIO 說明、電流與資訊流、V = I × R、計數器順序、完整預期結果、題目與解答位置，以及不必要的版本或教學安排敘述。
5. 核對頁碼、檔名、接點、程式及題目／解答一致性；更新受影響的自動檢查。
6. 重新產生 PDF 並渲染檢查受影響頁；涉及全篇寫法時檢查全篇。
7. 分開記錄文字檢查、軟體測試、韌體編譯與硬體實測，不以其中一項代替另一項。
8. 未獲當次授權，不 commit、push 或上傳雲端；不連帶修改正式 main、私有 QA、OLED 補充或其他週。
