## Week 5：燈光、畫面與倒數
> 可查資料或使用 AI；作品可現場操作或用手機展示。

**作品：**一顆能分別顯示紅、綠、藍及全關的 RGB 燈。

**特色：**RGB 是同一模組內的紅、綠、藍三種發光元件，本題一次只亮一色。

<aside class="safety">改線前拔除全部電源。先確認模組供電、訊號與限流方式；不確定時保持斷電。不移除或短接限流電阻通電。</aside>

**預期結果：**電腦要求紅、綠、藍、全關時，實物分別呈現對應狀態；不靠紀錄文字代替觀察燈色。

**驗證方法：**依序操作全關、紅、綠、藍、全關，展示實物與同次操作的電腦紀錄。

## 在 OLED 看見文字與數字
**作品：**OLED 顯示器，能顯示狀態、時間與一個可改變的示例數字。

**特色：**OLED 是小型顯示器。本題數字只是人工指定的展示值，不是感測器量測或遊戲得分。

### 預期結果
| 操作 | 應看到 |
|---|---|
| 啟動 | 狀態、時間、示例數字各自可辨認 |
| 把示例 3 改成 4，再改回 3 | 同一位置顯示新數字；其他文字不消失 |

**驗證方法：**展示三次畫面，確認文字不超出螢幕、不重疊，並與程式回報一致。

### Q2．有供電，為什麼仍可能沒有新畫面？
假設程式先把新文字畫在 ESP32 的記憶體，再經通訊線傳到 OLED。現在只略過「傳送新畫面」這一步，供電與其他程式都不變。電腦的數字持續更新，OLED 可能如何？這能否證明 OLED 沒電？請用資訊傳遞路徑解釋。

## A．有燈色提示的倒數器
**作品：**30 秒倒數器，用 OLED 顯示狀態和剩餘時間，用 RGB 顯示紅綠交替。

**特色：**從綠燈開始，每三秒換色。倒數依實際經過時間計算，畫面更新速度不改變總時長。這週不計算遮光得分。

### 預期結果
| 操作或條件 | 應有的反應 |
|---|---|
| 準備好但尚未開始 | IDLE（待機），30 秒，燈全關 |
| 開始 | RUNNING（進行），從 30 秒倒數、先綠燈 |
| 經過 3、6、9 秒 | 依序紅、綠、紅 |
| 進行中再次要求開始 | 不改原開始時間 |
| 中止 | ABORTED（中止），燈全關，剩餘時間凍結 |
| 中止或到期後直接要求開始 | 拒絕；先重新準備，再開始新一輪 |
| 檢查到已滿 30 秒 | EXPIRED（到期），剩 0，燈全關 |

**驗證方法：**展示一輪自然到期、一輪中途停止。用程式自動記下的時間、OLED 和實物燈色核對，不用人手卡在毫秒邊界。

保持總長與換色規則不變，只讓畫面從約每 0.2 秒更新改為每 1.5 秒更新。預期畫面較常跳秒，但總倒數仍是 30 秒。比較後恢復原更新速度。

<aside class="safety">發熱、異味或持續重啟時直接斷電。軟體中止不是切斷電源；不加入舵機或額外負載。</aside>

## 畫面與真正剩餘時間
### Q3．兩次刷新之後，究竟剩多久？
一輪 30 秒倒數，開始後 0.8 秒刷新一次，再過 1.3 秒刷新第二次。畫面只顯示整秒，規則是把剩餘秒數向上取整，例如 1.2 秒顯示 2。

第二次刷新時真正剩幾毫秒、應顯示幾秒？另一個程式「每刷新一次就減一秒」也顯示 28，能證明兩種算法相同嗎？請用計算說明。
<div class="write-space" style="height:49mm"></div>

### Q4．顯示恢復，就能直接續跑嗎？
倒數中用程式模擬「顯示傳送失敗」，不拔帶電線。程式中止，燈全關；OLED 還留著舊的 RUNNING 畫面。稍後 OLED 恢復通訊回應，但半個畫面仍不亮。

你會依什麼判斷目前是否仍在倒數？要檢查哪些結果才能重新準備並開始？說明為什麼只收到通訊回應還不夠。
<div class="write-space" style="height:57mm"></div>

**驗證方法：**作品 A 須提供上述軟體模擬與恢復操作；故障時中止、全關燈，重新準備應被拒絕。通訊與畫面均恢復後，仍須明確重新準備，再開始全新一輪。

## B．用兩顆按鈕操作倒數
**作品：**桌上倒數器，用一顆按鈕調整時間，另一顆開始或中止；OLED 顯示結果。

**特色：**只用按鈕與 OLED。每次調整 10 秒，範圍 10～60 秒；按住只接受一次，放開才接受下一次。

### 預期結果
| 操作 | 應有的反應 |
|---|---|
| 啟動，按調整一次 | 待機，10 → 20 秒 |
| 按開始 | 從 20 秒倒數 |
| 進行中按調整 | 不接受，不改總時長 |
| 再按開始鍵 | 中止，剩餘時間固定 |
| 放開，再按開始鍵 | 重新從完整 20 秒開始，不是續跑 |
| 到期 | 0 秒，DONE（完成），到期只記一次 |
| 未計時，60 秒再調整 | 回 10 秒 |

兩鍵重疊時不接受新動作，但不撤銷先前已接受的單鍵。顯示通訊故障時停止並保持 FAULT（故障），排除後重新啟動才操作。

**驗證方法：**依表操作，展示長按只觸發一次與雙鍵不接受；電腦記錄與 OLED 狀態須相符。

### Q5．你用什麼決定還剩多少時間？
指出自己記住開始時刻及計算剩餘時間的程式，說明為何換成按鈕後，不能用「按鈕讀了幾次」或「螢幕更新幾次」當作經過秒數。

## C．可以暫停、續跑的倒數器
**作品：**沿用兩顆按鈕與 OLED，讓使用者暫停後能接著剩餘時間繼續。

**特色：**每次調整 5 秒，範圍 5～30 秒。重新啟動回待機 5 秒；到 30 再調整回 5 秒。按住只接受一次，雙鍵不接受新操作。

### 預期結果
| 條件與操作 | 應有的反應 |
|---|---|
| 待機或完成時按調整 | 加 5 秒，回待機 |
| 待機或完成時按開始 | 從完整選定時間倒數 |
| 進行中按開始／暫停 | PAUSED（暫停），剩餘毫秒固定 |
| 暫停期間等待五秒 | 剩餘時間不變，畫面仍可更新 |
| 暫停或進行中按調整 | 不接受，不改選定時間 |
| 暫停後放開再按開始／暫停 | 從保存的剩餘時間續跑 |
| 到期或顯示故障 | 到期只記一次；故障保持停止，不得續跑 |

**驗證方法：**選十秒開始，任意時刻暫停，等五秒後續跑。程式自動記下暫停前後的剩餘毫秒，兩筆必須相同；不要求手動剛好按在 3.2 秒。

### Q6．暫停的五秒如何被排除？
用自己的程式說明暫停時保存什麼、續跑時如何使用，及為何只保存畫面上的整秒可能遺失時間。
