# 18 週課程規劃：IoT 玩具與互動硬體設計

## 一、課程目標

學生從 ESP32-S3、安全接線、感測器與致動器開始，先做出不依賴網路的
互動硬體，再逐步加入 HTTP、WebSocket、MQTT、後端、Database、
structured log 與手機操作。期末題目由學生自行決定，但必須同時展示
實體行為與有明確用途的軟體。

軟體的用途至少包括下列一項，完整期末作品原則上應包括兩項：

1. 記錄感測值、狀態、操作、錯誤、得分或其他事件，並可查詢歷史。
2. 協助使用者即時監看、設定模式、發出命令或確認執行結果。

## 二、共同資料流

```text
感測器／按鈕／手機輸入
  -> ESP32-S3
  -> 燈、聲音、顯示、舵機或馬達
  -> Wi-Fi + HTTP 或 MQTT
  -> 學生自行撰寫的 Backend
  -> Database + structured log
  -> WebSocket
  -> 手機前台

手機命令
  -> Backend 記錄與派送
  -> ESP32-S3 判斷並執行
  -> 回傳成功、失敗或 timeout
  -> 手機更新結果
```

### Week1：知道買什麼，讓電腦能編譯程式

**共同成果：**能辨認要買的課堂材料，找到並重新開啟自己的 Hello 程式，編譯成功。

1. 先看一個簡短的按鈕／光線顯示成品，知道課程會做出什麼，再看採購實物照片、規格與數量。
   不先講完整網路架構或逐項解釋尚未使用的元件。
2. 安裝 Arduino IDE、ESP32 套件，選定課堂板型與必要設定。設定用一張對照表，不要求背誦。
3. 開啟 Hello，儲存工作副本、編譯，再改一行文字重新編譯。用實際錯誤訊息確認是否成功。
4. 知道檔案放哪裡、下週從哪裡打開；備妥筆電與 USB 資料線，依清單安排第二週取得元件。

**為什麼需要：**IDE 用來寫與檢查程式；開發板套件使電腦能替 ESP32 編譯。
此時只有電腦，不要求找 Port、安裝未出現裝置的驅動、Upload 或 Serial 實機輸出。
Flash／PSRAM 原理、GPIO 全表、HTTP／MQTT／資料庫細節及完整零件原理解說移出本週操作主線。
採購清單與全學期要求仍可查閱，不逐頁當成第一次課必須理解的內容。

**進入下一週前：**學生能重新開啟檔案並編譯；元件尚未到手不視為操作失敗。

### Week2：同一顆按鈕，做三種操作
先裸板上傳 Hello、確認 Serial Monitor，再從空麵包板接一顆按鈕。Hello 與按下／放開測試是準備，不另算作品。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 按鈕計數器：按一下加一次，長按不連加 |
| Q2 | 狀態切換器：每次按下切換 ON／OFF，長按保持 |
| Q3 | 單鍵碼表：按下開始、暫停、繼續；暫停時間不算入，RST 清零 |
| Q4 | 先說明內部上拉如何讓放開的按鈕有明確讀值，再推想沒有上拉會怎樣 |

三件共用一顆按鈕的接線。按鈕用來選擇操作時機，變數分別保存次數、開關狀態與計時結果。
電阻在第一次按鈕成功後，為了解釋「放開時為什麼仍有確定電壓」出現；不另接外部電阻才准做作品。
短路反例只在紙上推理，電阻量測與完整分壓推導保留補充。

### Week3：把光線變成可看、可留、可數的結果
先讓 OLED 顯示固定文字，再加入光敏。每週重新接線，不假設 Week2 電路還在；按鈕只在需要的作品接入。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 光線觀測器：OLED 即時顯示光敏讀值，遮光時有可觀察反應 |
| Q2 | 光線快照：按下保存，目前值繼續變，保存值不變；長按只存一次 |
| Q3 | 可暫停的遮光計數器：一次未遮光到遮光只加一，按鈕切換計數／暫停；恢復時若已遮住，須先移開再遮住才計次 |
| Q4 | 解釋 raw 如何產生，以及只看到 0 能否確定很暗 |

光敏取得訊號，OLED 讓作品自行顯示；Q2 按鈕選保存時機，Q3 選是否計數。
Q3 分界依本組未遮光／遮光讀值設定，支援兩種變化方向，不照抄固定數字。
先有讀值才解釋 ADC 與模組分壓。固定電阻實驗、多筆取樣、最小最大值仍非本週共同題目。
OLED 沿用既有採購規格與數量，Week3 前備妥，不要求重買。

### Week4：顯示、提示與比較環境
新增 DHT 是為了量到光敏不能提供的溫度、相對濕度。先接需要的模組並看到有效讀值，再進入判斷與保存。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 環境顯示器：顯示光線、溫度、相對濕度及單位 |
| Q2 | 環境超標提示器：DHT 讀值與設定比較，分別指出溫度、濕度是否大於分界；等於算未超過 |
| Q3 | 兩個位置的環境比較器：按下依序保存 A、B，顯示 B−A；第三次開始新 A 並清除舊 B；無效讀取不覆蓋保存值 |
| Q4 | 當次讀取失敗，仍顯示未標示的舊值會造成什麼誤會？如何呈現？ |

三題都可等效選 OLED 或 Serial Monitor，Ans／program 各有相符版本。不使用 OLED 的學生不用接 OLED。
Q1 用光敏與 DHT；Q2 只用 DHT；Q3 用 DHT 與按鈕，不強迫按鈕或光敏加入每件作品。
28°C、65%RH 是練習分界，不是健康標準；改設定驗證，不以火、熱風或水改變環境。
DHT 每 2.5 秒讀一次，保存最近有效結果，不宣稱所有感測器在按下瞬間同步量測。
沒有有效結果時顯示 `--`，不能用舊值或 0 冒充成功。這項顯示選擇不改其他週安排。

### Week5：同一顆 RGB，表示三種用途
新增 RGB 是為了不讀小字也能辨認狀態。核對模組及限流後，先做單色點亮測試；測試不是第四件作品。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 桌面狀態燈：按鈕切換可打擾／忙碌／離開，OLED 文字與綠／紅／藍一致 |
| Q2 | 光線狀態燈：依本組光線判斷，未遮光亮綠、遮光亮藍；未完成設定或讀值端點時不顯示正常燈色 |
| Q3 | 溫濕度提醒燈：正常綠、溫度超過分界紅、只有濕度超過時藍；兩項都超過以紅優先，讀取失敗熄燈並提示 |
| Q4 | RGB 照到光敏，為什麼會改變作品自己的判斷？如何擺放與核對？ |

三題分別使用按鈕、光敏、DHT 作輸入，不要求三種輸入同時接上。OLED 顯示對應文字與讀值。
Q3 沿用 Week4 的比較，不加倒數、選單、蜂鳴或新規則。未確認 RGB 接法與限流前不得通電。

### Week6：手動與感測控制的紙指針
新增舵機是為了把指示變成實體位置。全班保留舵機操作，先看畫面預覽，再核對供電與安全行程，最後才啟用動作。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 手動紙指針：按鈕選 0～6 格，OLED 命令與實物位置可對照 |
| Q2 | 光線紙指針：未遮光／遮光對應 0／6 格 |
| Q3 | 溫度紙指針：依練習分界 25°C、28°C，對應 0／3／6 格 |
| Q4 | GPIO 訊號與舵機供電各做什麼，為什麼需要共同 GND？ |

三題都是真正的紙指針作品；畫面預覽、供電量測不是另外兩題。只用輕量紙指針，不能改成承重機構。
舵機供電先不接，先核對四顆 1.5 V AA／開關電池盒／降壓模組的實物規格、輸入與輸出、極性、帶載能力，
再斷電接好共同 GND、訊號、停止按鈕，固定本體並確認安全行程。供電未確認不能靠改旗標跳過。
外部電源關閉時先啟用，OLED 顯示允許後才由人開外部電源；最多啟用 30 秒、位置命令至少隔 1 秒。
STOP、OLED 失聯及本題所用感測器無效都停止；停止後仍需人工關外部電源，重新開始須 RST。
供電、共地、固定、發熱／卡住應對與斷電收納不能刪減。每位學生應輪流操作，不以命令文字冒充實際到位。

| 題號 | 作品與完成條件 |
|---|---|
| Q1 | 環境比較站：保存 A、B 光線與溫濕度，OLED 比較，RGB 表示保存進度；不接舵機 |

### Main、Ans、program 的改寫方式

**Main 是課堂作品要求與作答，不是每週再辦一次正式考試。** Week2～7 固定三題實作（Q1～Q3）加一題觀念（Q4）。
三件作品由簡到深，各有用途與可展示結果。每題依序提供作品用途、成品示意（Week4 可為 OLED 或 Serial Monitor）、預期反應、驗證方式，最後才留一個必要回答；Q4 不再重抄實測資料。
保留先自行挑戰的可能，不提供答案程式或逐步接法；但題意、安全條件及必要名詞須完整。
實作展示能證明的部分不再抄表或重問，紙本只留必要讀值、判斷理由與足夠書寫空間。
Week1 保留安裝與設定步驟，不為套用這個分工把初次電腦操作藏到 Ans；Week8 正式實作考另訂規則。

**Ans 是跟著做出作品的操作講義，最後才查完整答案與補充。** 不再以整份 Main 填答卷開場。

1. 首頁直接指出本週作品、會用到的已學知識、本次新增部分，以及空麵包板的開始狀態。
2. 按實作順序分段：必要安全 → 本週完整實物接點圖與接線 → 要開的程式及必要設定 → 成功畫面 → 就地排錯。
3. 一張接線圖以本段實際元件為主，兩端按實物印字標示；同堂換段列清楚保留、移除、新增，不只靠線色。
   每週均提供從空板搭建所需的完整接線總圖、表與步驟，不以跨週引用或資訊流圖代替。
4. 每完成一段再用短說明解釋本週新原理。先說是什麼與剛才用途，再比較單一修改的安全反例。
5. 後段用 Main 相同題號列直接答案，簡短題先給結論再說理由；實測題用可接受的反應及示例，
   不捏造全班一致的數字。不要再把整份題幹與空白表格複製一次。
6. 長推導、舊變形題及進階程式移到清楚標示的補充；已教的 OLED 設定簡短提醒與引用，不逐週重印長篇。
   Week4 依所選顯示提供 OLED 或 Serial Monitor 的必要設定，Ans／program 兩種版本都要有。
   但本週實際使用的接線、必要設定及先斷全部電源再拆線收納的步驟，必須在本週直接找到。

**program 放完整程式，Ans 只指出這一步開哪個檔。** 保留 Arduino 同名資料夾與 .ino，
用最小測試及完整作品的必要檔案支援本週步驟，不讓學生從 PDF 拼湊程式。
一個版本對應一組接線及預期畫面；先核對 GPIO、位址、程式庫與實物，不靠填 true 解除未知條件。
每支程式保留必要的短中文註解，指出本週新增或修改之處，舊範例不混在共同必做的開檔順序。
GitHub 與雲端是否提供 Main、Ans 或程式仍分別依發布授權，不能由教材分工推定全部公開。

改寫先從維護來源刪除重複與不再必做的內容，不只縮字或更換封面。核對 Main 的每項要求都有
Ans 做法、程式及可觀察結果，再核對 Ans 沒有多出另一套必做；重建後逐頁檢查圖、字與程式連結。
不預先承諾固定頁數，以能快速找到接線、程式與成功畫面且不重複為準。

## 六、期末作品最低要求

- 一個可安全運作的實體作品，以及可解釋的使用情境。
- ESP32-S3 或經教師核准的控制板。
- 至少一種實體輸入與一種實體輸出；例外須在第10週第一次專題報告獲准。
- Wi-Fi，以及 HTTP 或 MQTT 裝置通訊。
- 學生自行撰寫、可重新啟動的 Backend。
- Database、歷史查詢與 structured log。
- 手機可用前台，至少包含即時狀態、歷史資料、操作或設定，以及錯誤／離線呈現。
- WebSocket 即時更新；有控制行為時需記錄 command、result／ack 或 timeout。
- 至少一項自動反應、狀態機或排程。
- 至少三種測試情境，其中一種是斷線、錯誤輸入、感測異常或服務停止。
- 原始碼、接線圖、資料流圖、資料格式、BOM、重建步驟、AI 使用與驗證紀錄、已知限制。

Blynk、ThingSpeak、Node-RED 或現成 Dashboard 可以作輔助，但不能取代
學生自行撰寫的裝置端、Backend、Database 與手機介面核心成果。
