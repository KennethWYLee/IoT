# 18 週課程規劃：IoT 玩具與互動硬體設計

## 一、課程目標

學生從 ESP32-S3、安全接線、感測器與致動器開始，先做出不依賴網路的
互動硬體，再逐步加入 HTTP、WebSocket、MQTT、後端、Database、
structured log 與手機操作。期末題目由學生自行決定，但必須同時展示
實體行為與有明確用途的軟體。

軟體的用途至少包括下列一項，完整期末作品原則上應包括兩項：

1. 記錄感測值、狀態、操作、錯誤、得分或其他事件，並可查詢歷史。
2. 協助使用者即時監看、設定模式、發出命令或確認執行結果。

## 二、共同資料流

```text
感測器／按鈕／手機輸入
  -> ESP32-S3
  -> 燈、聲音、顯示、舵機或馬達
  -> Wi-Fi + HTTP 或 MQTT
  -> 學生自行撰寫的 Backend
  -> Database + structured log
  -> WebSocket
  -> 手機前台

手機命令
  -> Backend 記錄與派送
  -> ESP32-S3 判斷並執行
  -> 回傳成功、失敗或 timeout
  -> 手機更新結果
```

## 四、Week 2～7硬體學習路徑

Week 2保持既有入門教材。Week 3從電表、分壓與ADC延伸室內光／遮光分類；
Week 4加入DHT11雙感測與蜂鳴器事件；Week 5處理RGB、OLED與計時；
Week 6驗證SG90外部供電與0～6紙指針；Week 7整合紅綠燈遮光挑戰。

遊戲規則與逐週教學對照集中在[詳細設計](../course_materials/traffic_light_challenge_design.md)。
OLED增加為共同顯示需求，不另加七段顯示器；確切型號與供電待核准後公布。
DHT11有Week 4共同用途，不強制加入遊戲。Week 11以前不接網路。
所有新接線、驅動與供電仍須指定實機驗證，不把紙上規劃當成可直接上電。

## 五、第8～17週評量安排

### 第一次專題報告：第8週題目與技術可行性

每組只參加一次預約時段，帶來：

1. 想製作的玩具或硬體、目標使用者與核心操作。
2. 一個可運作的硬體片段，不要求完整成品。
3. 軟體要記錄什麼，或如何協助使用者操作。
4. 裝置、後端、Database 與手機之間的資料流。
5. 已有材料、擬加購材料、供電／驅動風險與最低可驗收結果。

第8週是第一次專題報告，也是期中小組成果，不另收內容重複的期中整合包。

## 六、期末作品最低要求

- 一個可安全運作的實體作品，以及可解釋的使用情境。
- ESP32-S3 或經教師核准的控制板。
- 至少一種實體輸入與一種實體輸出；例外須在第8週獲准。
- Wi-Fi，以及 HTTP 或 MQTT 裝置通訊。
- 學生自行撰寫、可重新啟動的 Backend。
- Database、歷史查詢與 structured log。
- 手機可用前台，至少包含即時狀態、歷史資料、操作或設定，以及錯誤／離線呈現。
- WebSocket 即時更新；有控制行為時需記錄 command、result／ack 或 timeout。
- 至少一項自動反應、狀態機或排程。
- 至少三種測試情境，其中一種是斷線、錯誤輸入、感測異常或服務停止。
- 原始碼、接線圖、資料流圖、資料格式、BOM、重建步驟、AI 使用與驗證紀錄、已知限制。

Blynk、ThingSpeak、Node-RED 或現成 Dashboard 可以作輔助，但不能取代
學生自行撰寫的裝置端、Backend、Database 與手機介面核心成果。

## 八、教師示範與進階方向

- 智慧停車與 UCI K-4 4WD：感測、馬達控制、事件紀錄與手機監看。
- 夾取、投擲或反應玩具：致動器、命令、得分與使用紀錄。
- 智慧教室：占用、環境、照明、告警與歷史分析。
- 手機視覺：手機／筆電先完成辨識，再將結果交給 Backend 與 ESP32。
- ROS 2、Gazebo、Nav2：完成本課資料與控制架構後的機器人進階路線。
