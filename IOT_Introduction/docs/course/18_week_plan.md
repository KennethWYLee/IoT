# 18 週課程規劃：IoT 玩具與互動硬體設計

## 一、課程目標

學生從 ESP32-S3、安全接線、感測器與致動器開始，先做出不依賴網路的
互動硬體，再逐步加入 HTTP、WebSocket、MQTT、後端、Database、
structured log 與手機操作。期末題目由學生自行決定，但必須同時展示
實體行為與有明確用途的軟體。

軟體的用途至少包括下列一項，完整期末作品原則上應包括兩項：

1. 記錄感測值、狀態、操作、錯誤、得分或其他事件，並可查詢歷史。
2. 協助使用者即時監看、設定模式、發出命令或確認執行結果。

## 二、共同資料流

```text
感測器／按鈕／手機輸入
  -> ESP32-S3
  -> 燈、聲音、顯示、舵機或馬達
  -> Wi-Fi + HTTP 或 MQTT
  -> 學生自行撰寫的 Backend
  -> Database + structured log
  -> WebSocket
  -> 手機前台

手機命令
  -> Backend 記錄與派送
  -> ESP32-S3 判斷並執行
  -> 回傳成功、失敗或 timeout
  -> 手機更新結果
```

### Week1：知道買什麼，讓電腦能編譯程式

**共同成果：**能辨認要買的課堂材料，找到並重新開啟自己的 Hello 程式，編譯成功。

1. 先看一個簡短的按鈕／光線顯示成品，知道課程會做出什麼，再看採購實物照片、規格與數量。
   不先講完整網路架構或逐項解釋尚未使用的元件。
2. 安裝 Arduino IDE、ESP32 套件，選定課堂板型與必要設定。設定用一張對照表，不要求背誦。
3. 開啟 Hello，儲存工作副本、編譯，再改一行文字重新編譯。用實際錯誤訊息確認是否成功。
4. 知道檔案放哪裡、下週從哪裡打開；備妥筆電與 USB 資料線，依清單安排第二週取得元件。

**為什麼需要：**IDE 用來寫與檢查程式；開發板套件使電腦能替 ESP32 編譯。
此時只有電腦，不要求找 Port、安裝未出現裝置的驅動、Upload 或 Serial 實機輸出。
Flash／PSRAM 原理、GPIO 全表、HTTP／MQTT／資料庫細節及完整零件原理解說移出本週操作主線。
採購清單與全學期要求仍可查閱，不逐頁當成第一次課必須理解的內容。

**進入下一週前：**學生能重新開啟檔案並編譯；元件尚未到手不視為操作失敗。

### Week2：首次上傳，一顆按鈕讓數字改變

**共同成果：**先看到 ESP32 傳回文字，再做到按一下加一次、按住不連加的計數器。

1. 辨認實際板子與 USB 資料接頭，裸板上傳 Hello，開 Serial Monitor；改文字、重傳，看到新文字。
2. 為了接按鈕，斷電辨認本次使用的麵包板相通孔與按鈕接點；只查本次需要的孔，不先填整張孔位考卷。
3. 接一顆按鈕，沿用上傳與文字視窗，先顯示按下／放開。斷電改線、核對後才上電。
4. 看過兩種狀態後，解釋 GPIO 對 GND 的電壓，以及晶片內部上拉電阻在放開時的作用。
5. 保持同一組接線，換成一次按下加一。參考程式先能處理去抖；成功後再對照讀取、保存次數與輸出。

**為什麼需要：**按鈕讓人決定何時改變結果；麵包板讓導線與按鈕接在一起；變數保存已按幾次。
電阻以「為什麼放開時仍有明確讀值」引入，不為了認識電阻另加外部電阻支路。
正常接法理解後才用紙圖比較沒有上拉、電阻被導線取代；不把危險短路接到實物。
Ω、kΩ 與 V = IR 可隨正常回路簡短解釋，完整推導與阻值量測是補充，不阻擋第一次計數成功。

**刪減與後移：**第二顆按鈕減法保留為同接線方法的延伸；長按自動連加、0～20 全套邊界、
雙鍵重疊與恢復、詳細電流計算不列為所有人本週共同必做。
**進入下一週前：**能辨認接點、完成一顆按鈕、上傳相符程式；放開再按才增加下一次。

### Week3：光線有數字，作品自己顯示與保存

**共同成果：**光線改變時 OLED 的目前值跟著變；按一下保存當時讀值，之後目前值變、保存值不變。

1. OLED 先單獨顯示固定文字，確認接點、程式與畫面都對；按鈕沿用 Week2 的已確認接法。
2. 只新增光敏的讀取，將沒遮光與遮光的數字顯示在 OLED；必要時用 Serial 隔離排錯，
   不另做一套以電腦抄錄為主的作業。記下必要的本組觀察，不抄大量樣本。
3. 沿用一次按下的操作，在 OLED 保存當時光線數字；不先做一次三筆。
4. 同一畫面區分目前值與最近保存值；保留原光線快照作品，不另加資料庫或歷史列表。

**為什麼需要：**光敏取得光線訊號；按鈕選擇保存時機；OLED 讓人直接看作品，不必一直盯電腦。
先有讀值才說明 ADC 把接腳電壓轉成整數 raw。需要回答遮光為何使數字變化時，用本片模組圖
連回電阻與分壓，不突然拆掉作品改接兩顆固定電阻。供電與量電壓的安全條件仍在操作之前。

**刪減與後移：**原一次三筆、可暫停遮光計數、最小／最大值各留作進階選題，不要求全班全部完成。
1 kΩ／10 kΩ 獨立分壓實驗、完整 ADC 換算與色環推導移為補充。
本週有光敏與 OLED 兩種新模組，必須分開成功後再合併；不能把「三個都先接起來」當第一步。
OLED 沿用既有規格與數量，需於本週前備妥；Week1 採購頁已同步提醒 Week3 首次使用。
**進入下一週前：**能分別指出感測器訊號、按鈕與 OLED 接點；能展示目前值與保存值的差別。

### Week4：加入溫濕度，沿用已會的紀錄方式

**共同成果：**按一下，留下光線與溫濕度的一筆環境紀錄；讀不到溫濕度就明確顯示失敗。

1. 保留已成功的光敏與 OLED 接法，只新增 DHT11 接線與必需的程式庫。開啟本週環境程式，
   先確認 OLED 新增的溫度、濕度及單位，不修改舊感測器接線；Serial 僅用於排錯。
2. 確認原光敏顯示仍會隨遮光改變，再對照同一畫面的兩種感測資料。先確認讀值，不先做品質評分。
3. 沿用按鈕的一次按下操作，保存當次光線及最近一次溫濕度，在 OLED 區分目前與保存結果。
   OLED 不再是選做；版面沿用，不另設排版考題，也不要求所有感測器同一瞬間取樣。

**為什麼需要：**光敏只能告訴我們光線，DHT 才能加入溫度與濕度。程式庫負責讀取這種感測器，
不要求學生先學它的通訊時序。看到紀錄後才簡短說明「同一行不表示同時量到」；
不能把舊值冒充剛讀到的新值，未取得或讀取失敗須清楚標示。

**刪減與後移：**移除開場的 220／330 Ω 獨立量測；蜂鳴器、遮光計次、失敗模擬指令、
多層品質規則、1000／1001 ms 收錄邊界、成功／跳過計數均不放進共同完成的第一個版本。
保留為已有基本作品後的進階選題；失敗不能填 0 或偽造正常值的要求仍保留。
**進入下一週前：**能讓 DHT 單獨工作，沿用舊元件完成一次紀錄，並分辨成功與讀取失敗。

### Week5：讓 RGB 表示已量到的環境狀態

**共同成果：**保留光線、溫濕度與按鈕保存，用 RGB 的兩種燈色表示光線判斷結果，OLED 同時顯示對應文字。

1. 不拆掉已成功的環境作品。斷電新增 RGB，先核對接法與限流，用最小程式分別測試燈色與關閉。
2. 用本組沒遮光、遮光的觀察，說清楚何時顯示哪一種狀態，再讓 RGB 表示同一個結果。
   不預設遮光一定使數字變大；如果兩種情況無法分開，先查環境、接線及讀值，不硬套示例分界。
3. DHT 保留原來的讀值與單位，按鈕保留保存功能；不再同時新增溫濕度警報、計時或選單。
4. 改變遮光情況，核對 OLED 的目前值、狀態文字與實際燈色；保存值依原按鈕操作更新。

**為什麼需要：**OLED 顯示數值，RGB 讓人不必讀小字就能辨認狀態。燈色表示程式判斷，
不是另一顆感測器。RGB 的限流電阻放在實際燈路中解釋，沿用 Week2 電阻概念。

**刪減與後移：**倒數器、調時、暫停續跑、三秒紅綠交替及完整故障矩陣保留為進階舊例，
不列入這週共同必做或 Week8 必考。讀不到資料時不可亮出假稱正常的結果。
RGB 不得直照光敏造成自己的燈反覆影響判斷；先確認擺放及正常反應，不另加光干擾抄表題。
**進入下一週前：**能指出燈色依哪筆資料判斷，並核對 OLED 與實際燈色一致。

### Week6：讓數字變成紙指針，保留全班舵機實作

**共同成果：**在已確認的安全範圍，指定格數讓舵機紙指針移到相應位置，並能停止、正確斷電。

1. 沿用 OLED 預覽格數與位置命令，先看紙刻度與預期方向；示例角度不是實物安全行程。
   舊光敏、DHT、RGB 與按鈕的接線保留，先不讓其他感測器自動觸發新舵機動作。
2. 舵機先不接。依課前確認流程辨認外部供電的輸入／輸出、正負與測點，核對電表的電壓檔及插孔，
   實際量測輸出。沒有確認的供電規格、端子或帶載能力，就不能進入下一步。
3. 斷電接舵機供電、共同 GND 與訊號，固定本體及輕量紙指針；先試已確認行程中的少量位置，
   正常後才做原 0～6 格指示。每次觀察實物，不把程式印出的命令當成已到位。
4. OLED 顯示指定位置與停止狀態；開始、指定位置、停止的操作在題目與程式一致寫明，
   不把 Serial 輸入命令作為學生主要介面。接線、按鈕用途需先核對，停止事件不能同時觸發保存或新動作。
   驗證停止按鈕、啟用期限與斷電收納。原安全限制不因刪減題目取消。

**為什麼需要：**前面用文字和燈顯示結果，舵機把數字變成看得見的實體位置。
外部電源是為了供應舵機工作所需電力；GPIO 傳位置命令，不供應動作電力。
共地、電流路徑與訊號路徑在實際接線旁分開說明；危險反例只作紙上推理。

**刪減與後移：**加減兩格的變形題與完整七格公式推導移為進階。
保留舊感測器的顯示，不在本週同時重寫光線判斷、RGB 規則與 OLED 版面；完整互動留到 Week7。
不減少供電、共地、行程、固定、上電、停止、發熱／卡住應對及斷電檢查。所有學生輪流操作，
不能只由一名熟練組員完成就認定全組都會。
**完成標準：**指出電力與訊號分別走哪條線；命令與實物位置能對照；停止後知道仍需關哪些電源。

### Week7：用已學材料整合練習

**共同成果：**按指定需求連接已完成的按鈕、光敏、DHT、OLED、RGB 與舵機行為，展示輸入改變後的畫面與實體反應。

1. 從 Week6 已成功的接線開始，不全部拆掉重接；先確認各模組仍正常，再處理它們如何配合。
2. 題目先給作品用途、OLED 成品示意、操作與預期反應；用已練過的讀值、保存、燈色及位置控制組合，
   不另外加入計分、蜂鳴、倒數、網路、資料庫或新的零件。
3. 學生先嘗試，Ans 提供同一作品的分段實作與答案。未通時回到對應模組測試，不用反覆抄寫結果代替排錯。
4. 驗證正常操作與已教的停止、失敗處理；不新增一整套故障矩陣或額外交件，亦不是第二次實作考。

**為什麼需要：**前面每週聚焦一個新增部分，這週練習用同一需求安排資料、顯示與動作。
Week8 只考已共同教學且練習過的能力；進階舊遊戲不因保留在資料夾就成為必考。

### Main、Ans、program 的改寫方式

**Main 是課堂作品要求與作答，不是每週再辦一次正式考試。** 每週一個主要作品，
依序提供用途與本週新增功能、OLED 成品示意、必要操作與預期反應、驗證方式、少量有不同目的的問題。
保留先自行挑戰的可能，不提供答案程式或逐步接法；但題意、安全條件及必要名詞須完整。
實作展示能證明的部分不再抄表或重問，紙本只留必要讀值、判斷理由與足夠書寫空間。
Week1 保留安裝與設定步驟，不為套用這個分工把初次電腦操作藏到 Ans；Week8 正式實作考另訂規則。

**Ans 是跟著做出作品的操作講義，最後才查完整答案與補充。** 不再以整份 Main 填答卷開場。

1. 首頁直接指出本週作品、沿用的成果、本次新增部分及開始操作的位置。
2. 按實作順序分段：必要安全 → 實物接點圖與接線 → 要開的程式及必要設定 → 成功畫面 → 就地排錯。
3. 一張接線圖以本段實際元件為主，兩端按實物印字標示；列清楚保留、移除、新增，不只靠線色。
   同頁或相鄰頁提供完整接線總圖，避免只看新增線卻找不到完整電路；不以資訊流圖代替。
4. 每完成一段再用短說明解釋本週新原理。先說是什麼與剛才用途，再比較單一修改的安全反例。
5. 後段用 Main 相同題號列直接答案，簡短題先給結論再說理由；實測題用可接受的反應及示例，
   不捏造全班一致的數字。不要再把整份題幹與空白表格複製一次。
6. 長推導、舊變形題及進階程式移到清楚標示的補充；已教的 OLED 設定簡短提醒與引用，不逐週重印長篇。

**program 放完整程式，Ans 只指出這一步開哪個檔。** 保留 Arduino 同名資料夾與 .ino，
用最小測試及完整作品的必要檔案支援本週步驟，不讓學生從 PDF 拼湊程式。
一個版本對應一組接線及預期畫面；先核對 GPIO、位址、程式庫與實物，不靠填 true 解除未知條件。
每支程式保留必要的短中文註解，指出本週新增或修改之處，舊範例不混在共同必做的開檔順序。
GitHub 與雲端是否提供 Main、Ans 或程式仍分別依發布授權，不能由教材分工推定全部公開。

改寫先從維護來源刪除重複與不再必做的內容，不只縮字或更換封面。核對 Main 的每項要求都有
Ans 做法、程式及可觀察結果，再核對 Ans 沒有多出另一套必做；重建後逐頁檢查圖、字與程式連結。
不預先承諾固定頁數，以能快速找到接線、程式與成功畫面且不重複為準。

## 六、期末作品最低要求

- Database、歷史查詢與 structured log。
- 手機可用前台，至少包含即時狀態、歷史資料、操作或設定，以及錯誤／離線呈現。

- 至少一項自動反應、狀態機或排程。
- 至少三種測試情境，其中一種是斷線、錯誤輸入、感測異常或服務停止。
- 原始碼、接線圖、資料流圖、資料格式、BOM、重建步驟、AI 使用與驗證紀錄、已知限制。

學生自行撰寫的裝置端、Backend、Database 與手機介面核心成果。
