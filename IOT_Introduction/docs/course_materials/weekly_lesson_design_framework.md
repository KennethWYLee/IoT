# IoT 每週教材設計框架

更新日期：2026-10-07。依現行 Week4、Week5 Main、Ans、program 及教師課堂回饋整理。

本文件供教材維護者使用，不是學生另一本必讀講義。沿用的是作品安排與閱讀方式，
不是 Week4 的感測器、CSV 或題數。課程範圍以[18 週計畫](../course/18_week_plan.md)
及教師最新決定為準；[修訂準則](../teaching_drafts/week2_redesign/revision_guidelines.md)
保存先前決定。舊 notebook、來源與紀錄不能取代現行 Main／Ans／program。

## 一、Week4 的安排與可沿用的理由

Week4 先讓學生看到有效讀值，再加入用途不同、可以各自展示的作品。

| 題目 | 作品與學生看得到的成果 | 本題增加的能力 |
|---|---|---|
| Q1 環境顯示器 | 顯示光敏讀值、溫度及相對濕度；數字有名稱和單位 | 取得資料並顯示 |
| Q2 超標提示器 | 顯示哪一項超過門檻，以及目前是否警報 | 把讀值轉成明確判斷 |
| Q3 警報紀錄器 | 裝置顯示警報次數、累計時間及按鈕確認 | 區分一次事件、持續狀態與使用者操作 |
| Q4 電腦分析結果顯示 | 保存 CSV、產生報告，將分析送回裝置；三處結果一致 | 串起保存、分析、回傳與核對 |

Q3 不需要電腦工具，開機直接計次、計時；CSV 與電腦分析全部放在 Q4。
Q3 按 RST 或重新上電歸零；Q4 按電腦的「開始新紀錄」建立新檔並重設本次統計。
兩題的實體按鈕都只確認警報，不解除警報、不清空統計、不建立檔案。

可以沿用到其他週的理由是：前題已做出的能力成為後題的先備；每題仍有不同用途，
不是把接線、上傳及展示拆成三道題。增加一個功能時，先說它解決什麼需要。

**不能直接照搬的部分：**DHT、28°C／65%RH 練習門檻、警報規則、CSV、USB 回傳、
電腦工具及四件完整作品都屬於 Week4，不是每週共同要求；上述門檻也不是健康或安全標準。

## 二、先做出來，再解釋原理

每件作品按以下順序教，不要求所有段落套用同一組標題：

1. 說明作品用途及預期畫面或動作。
   第一次用到的元件或軟體部分，先用一句話說它是什麼、此處接收什麼、負責什麼及產生什麼結果。
2. 說明當下必需的安全、實物辨認及操作條件。
3. 分段接線、開啟對應程式、完成必要設定。
4. 看正常結果；未成功時先排查這一段，不同時加入另一個元件。
5. 用剛完成的操作解釋本題的新概念，再比較限制或反例。

先做不等於先猜接法。安全警告、供電限制與必要辨認仍在操作前。
理論不集中擋在首次成功之前，也不把全部原理拖到整週結束才講。
頁數不是完成標準；優先刪重複、拆解難步驟及調整順序，不為完整性增加內容。

## 三、Main、Ans、program 的分工

| 檔案 | 學生要能找到的內容 | 不放什麼 |
|---|---|---|
| Main | 作品用途、特色、成品示意、預期行為、驗證方式、少量必要回答 | 解法、答案程式、冗長器材設定及接線步驟 |
| Ans | 安全與完整接線、對應檔名、必要設定、成功結果、就地排錯、直接答案及短原理 | 完整程式列印、整份重複題幹與空白填答卷 |
| program | 逐題對應的完整程式及真正需要的工具；必要設定與啟動提示 | 舊版學生入口、真實密碼、未說明的設定缺口 |

### Main：先說作品，再讓學生回答

- 每題先寫「要做什麼、做出來有什麼特色」，接著給預期畫面或動作。
- 用「操作什麼 → 應看到什麼」說明如何驗證，最後只問作品展示尚不足以證明的重點。
- 只看 Main 就應能理解需求與完成條件；不能依賴未提供的「本課規則」。
  這不表示未學過的學生能不經教學就完成；需要操作指引者使用 Ans。
- 名詞、單位、規則及邊界在需要時簡短說明。必要安全條件不能為了簡短而刪除。
- 實測值用本組結果；示例畫面與測試輸入明確標示，不讓學生照抄成實測答案。
- 同一筆資料只記一次。展示已證明的內容不再要求重抄規格、填影片位置或寫無關操作。
- 手動驗證給足操作時間；精確時間或邊界由程式紀錄、已給資料或測試核對。

### Ans：接線與程式必須容易找到

- 按 Main 題序提供操作，不以完整填答卷或長理論開場。
- 每週從空麵包板開始，直接呈現本週完整實物圖、接線圖、起點／終點表及分段步驟。
  共用維護來源可以重用，但「參考上週接線」不能取代本週完整接法。
- 寫明哪個物件、哪個部位、做什麼。例如「OLED 板上標示 SCK 的腳」，
  不把模組標字、ESP32 GPIO、麵包板孔位、程式變數或物理單位混成一句縮寫。
- 接線圖兩端有名稱，接點和方向可辨認；線色只輔助識別，不決定電氣功能。
- 先確認基本供電、單一輸入及顯示，再整合按鈕、統計或通訊；這些檢查不是額外作品。
- 開檔處直接給相符的 `.ino`，列本題確實要改的設定、執行位置與預期啟動訊息。
- 成功畫面旁放必要排錯。先寫症狀與第一個安全檢查，不要求學生翻完長篇故障清單。
- 直接答案按同題號呈現。實測題給填答方式及判斷依據，不虛構唯一讀值；再補短原理。

### program：完整、分檔、與接線一致

- 每件作品有可獨立開啟的完整版本；Arduino sketch 的資料夾與 `.ino` 同名。
  不把練習答案藏在基本程式的一個開關內，也不讓一支巨型程式靠許多開關變成所有作品。
- PDF 只保留解釋所需的短片段，完整程式另放每週資料夾；不要求學生從多頁拼程式。
- 題號、檔名、接線、設定、畫面文字、規則與失敗反應逐一對應。
- 未確認硬體保留必要安全保護，但清楚說明如何確認、設定未完成時會看到什麼。
  不能只改 `false` 為 `true` 就宣稱接法已安全；已確認的設定也不留成無解的空白範本。
- 區分 ESP32 程式與電腦工具，給足真正需要的依賴及開檔順序，不新增無關軟體教學。
- 修改唯一維護來源，再產生分發複本，以清單及雜湊核對；先保護教師或學生已改的版本。

## 四、作品由簡到深，但用途不能重複

- 依學生已會的操作與接線負擔排序，不只依題名或公式看起來是否簡單。
- 第一件作品先取得可看的正常結果；後面在已學能力上增加一個有用途的判斷、保存、
  控制或整合。這些是可選的安排，不是每週都須依序做顯示、警報及 CSV。
- 每題能說出不同用途與完成條件；若只是換數字、重抄資料或重做同一步，合併或刪除。
- 新元件先交代現在為什麼需要。每件只用必要零件，不把累積學過的感測器全塞進每題。
- 不只說按鈕用途。核對感測器、ESP32、OLED、RGB、舵機、電腦工具等各自的工作。
  例如按鈕送出保存請求，ESP32 保存資料，OLED 顯示保存結果；不能寫成按鈕保存或螢幕量測。
  同一元件換用途時只提醒改變的功能，例如 RGB 從表示保存進度改為表示目前環境，不重抄整張清單。
- 深度來自可以驗證的功能與判斷，例如持續狀態不重複計次、確認不等於恢復、
  回傳後核對裝置結果；不是增加空白表、抄寫或頁數。
- 若室內環境不易改變，可用已說清楚的設定或測試輸入驗證判斷。
  改門檻只能證明判斷規則，不能稱為量到環境改變；真實變化需安全、可行且如實記錄。

Week2～7 保留 Q1～Q3 三件用途不同的作品；Q4 連到已教內容的可觀察操作，
不必另造大型作品。Week4、Week5 已另獲批准四件完整實作；Week5 依序為桌上狀態燈、
倒數提醒燈、自動小夜燈及環境巡檢與比較，不能推定其餘週也要新增第四件大作品。Week1 尚無元件，保留採購、
Arduino／ESP32 設定與編譯；考試、報告、出國及保留週依原目的，不套固定題數。
不因此增加零件、功能、作業量、配分或更動週次。

## 五、概念、圖與反例如何放

概念第一次需要理解時，依序說明：**它是什麼 → 在剛才的作品做什麼 → 具體例子
→ 限制及容易混淆的地方**。不能用另一個陌生名詞解釋陌生名詞，也不先講「它不是什麼」。

- 名稱對回照片、接線、程式或畫面上的對象。標題直接寫作品、操作或概念，不用口號、
  製作說明或「不另外學一套程式」等繞路句。
- 每個重要數字交代來源、對象、單位及參考點。公式先定義符號，再用當前操作需要的
  一個例子列已知、代入、算出結果及解釋；以單位、回算或不同實作檢查，不加不必要推導。
- 電流路徑與資訊流分開。電流圖指出電源、元件及返回 GND 的路；資訊圖指出資料來源、
  判斷、顯示與回應方向。圖上交代箭頭、接點、交叉、數字與符號的意義。
- 接線圖回答「實際接哪裡」，原理圖回答「為什麼」；資訊流圖不能代替接線圖。
- 先說正常情況，再一次拿掉或改動一個元件、接點或程式設定，比較預期差別。
  例如 Week4 紙上拿掉 DATA：仍可能供電，卻收不到完整資料；不能把失敗讀值寫成 0。
- 危險錯接只作紙上或模擬推演，不讓學生帶電拔線製造故障。反例不額外變成每週交件。
- 已學概念只短提醒；本題原理解說連回剛才的結果。實拍、教學示意、模擬及實測分清楚，
  不猜補照片上的腳位、晶片或讀值，也不把示例輸出填成執行證據。

## 六、正常、失敗與重置都要說得清楚

只列作品實際需要的情況，不把 Week4 全部狀態名稱硬套到其他週：

| 要核對的情況 | Main、Ans、program 必須一致的內容 |
|---|---|
| 初次成功 | 哪個操作後看到哪個結果，何時算完成 |
| 持續或再次發生 | 持續時是否更新、重複計次；何時才算新事件 |
| 使用者操作 | 短按、長按、確認或暫停改變什麼，哪些結果不改變 |
| 邊界與失敗 | 等於門檻、未設定、未取得有效讀值或斷線如何顯示 |
| 新紀錄或重啟 | 哪些歸零、保留、重新建立或已無法恢復 |
| 跨裝置結果 | 看哪一端才足以證明收到或執行，是否有新的回應 |

不能把失敗當成 0 或正常，也不能把舊值當目前有效結果。送出命令不等於已執行；
電腦顯示自己的統計不等於裝置收到。紀錄及分析只支持已收到的資料與聲明的觀察範圍。
不要求學生製造符合參考答案的數字，未觀察到預期差異也如實說明。

## 七、每週重新搭建與安全收尾

- 每週從空麵包板及未接線元件開始，累積的是知識、程式與同一批零件，不是上週電路。
- 同堂階段之間可保留已確認接線；明說保留、移除、新增及是否換程式，改線前斷電。
- 供電、邏輯電壓、腳位、控制器、外部電源及安全停止依確切實物與
  [硬體紀錄](../hardware/hardware_state.md)查核，不憑相似模組或線色推測。
- OLED 自 Week3 起為主要裝置顯示；Week4 可等效選 OLED 或 Serial 版。
  其他週不自動改成擇一；後段 OLED 也不取代既有手機前台或歷史紀錄。
- 每步可由學生實際操作，不要求第三隻手、帶電插拔或同時握多個裸露導體。
- 下課停止操作、保存原有必要檔案、關閉連線；關閉並斷開 USB 及所有外接電源，
  確認斷電後才拆跳線、模組並收納。此要求也適用後段網路及整合週的既有硬體活動。

## 八、套用與驗證

1. 讀本機 AGENTS、PROJECT、正式課程計畫及指定週現行來源。查 Git 狀態，保留無關工作。
2. 列本週主題、學生先備及現有作品；確認每項要求已教、已練且有可觀察結果。
   先刪重複及不必要要求，缺少安全或必要操作才補，不為模板增加活動。
3. 只讀 Main，逐題檢查能否理解作品、預期結果、測試條件與回答對象，不偷看 Ans 補題意。
   逐一指出每個元件的用途與資訊從哪裡來；若學生仍須猜誰量測、誰判斷、誰保存或誰顯示，先修題意。
4. 按 Ans 從空板走一遍，檢查接點、檔名、設定、成功畫面及就地排錯，確認不用猜前週狀態。
5. 核對程式、圖、數字、條件、失敗及重置；獨立驗算或用不同測試輸入查邊界，不只重讀答案。
6. 修改維護來源並重建受影響複本與 PDF。逐頁渲染讀圖，查裁切、重疊、缺字、圖表、
   程式片段、連結與手機／投影可讀性；不以檔案存在或成功產生取代檢閱。
7. 分開記錄文件與計算、主機／模擬測試、板型編譯、實機及學生試讀證據；沒做就明說。
   編譯成功不能證明接線、上傳或實體反應成功；也不能保證所有學生均能獨立完成。
8. 提供簡短修訂紀錄、已做檢查與待驗項目。正式評量、採購、報告與週次仍以核准規定為準。

教師要求 Claude 共修時，先和 Claude 確認上述分工再動筆。Codex 先讀現行來源，
Claude 先只看 Main，以首次操作的學生提出具體疑問；再讀 Ans／program 核對接線與結果。
Codex 修正後交回受影響段落查核，並獨立檢查程式與渲染。逐次記錄讀到的範圍、
採用及未採用的意見，不把模型同意當成學生試用或實物已成功，也不替工具擴張永久權限。

工具及當週產生方法查[scripts 說明](../../scripts/README.md)與該週 README，
不拿舊 notebook 的建置指令覆蓋現行教材。僅改本框架時，只查文件、連結、差異及規則一致性，
不用重建學生 PDF，也不重新宣稱硬體通過。

GitHub 與教師雲端是不同發布範圍，依[目前教材入口](../../README.md)及教師當次授權核對。
一般 commit／push 不表示其他週答案或程式獲准公開；不改雲端分享權限。
本輪只整理本文件與修訂依據，不改其他週教材；commit、push 與雲端更新另依教師明確授權。
